# 重构契约 · 产物与发布

本契约落实 2026-11-21 修订稿第 6.8–10、12.1、12.5 和 12.6 节。阶段 0 约定类型、数据所有权和交付边界。实物适配、节点执行及清理由后续阶段接入。 [重构实施计划](项目交付重构实施计划.md)

## 执行图的值

```typescript
type ArtifactKind = 'FILE' | 'DIRECTORY' | 'DOCKER_IMAGE';
type ArtifactRef = { artifactId: string; instanceId?: string };
type ArtifactInstance = {
  instanceId: string;
  serverId: string | null;
  checksum?: string | null;
  path?: string;
  imageReference?: string;
  imageId?: string | null;
  digest?: string | null;
};
type ArtifactValue = {
  artifactId: string;
  type: ArtifactKind;
  name: string;
  instances: ArtifactInstance[];
} & ({ scope: 'PERSISTENT' } | { scope: 'TEMPORARY'; rootRunId: string });

type ServiceRef = { serviceId: string };
type ServiceOperation = 'DEPLOY' | 'CHECK' | 'ROLLBACK';
type ServiceTargetStatus = 'SUCCESS' | 'FAILED' | 'NEEDS_ATTENTION' | 'CANCELLED' | 'SKIPPED' | 'TIMED_OUT';
type HealthStatus = 'NOT_CHECKED' | 'HEALTHY' | 'UNHEALTHY' | 'UNKNOWN';

type ServiceTargetResult = {
  serverId: string;
  deploymentId?: string;
  rollbackOfDeploymentId?: string;
  plannedArtifactInstanceId?: string;
  artifactInstanceId?: string;
  status: ServiceTargetStatus;
  health?: HealthStatus;
  errorSummary?: string;
};

type ServiceResult = {
  operation: ServiceOperation;
  serviceId: string;
  status: ServiceTargetStatus | 'PARTIAL_SUCCESS';
  targets: ServiceTargetResult[];
};
```

- 具名 `ARTIFACT` 端口返回一个逻辑产物，逐目标信息在 `instances[]`。显式列表按逻辑 `artifactId` 去重。`SERVICE` 端口指向当前项目已有的服务。`SERVICE_RESULT` 由实际执行过的部署、检查或回滚节点产生，并按对应节点运行记录定位。任务目标在写入发布记录前失败时仍保留错误状态。
- 开始参数可以选 `{ artifactId }`，预览按部署目标解析每台机器要用的具体实例。显式给出 `{ artifactId, instanceId }` 时验证实例归属及对目标的可用性。同一目标有多个等价候选且没有已声明的选择规则时，要求选定具体实例。一个实例可经明确分发途径供多个目标使用，计划逐目标记录选取及验证证据。
- 构建和登记节点的 `FILE`、`DIRECTORY`、`DOCKER_IMAGE` 输出默认 `persist: true`。`persist: false` 产生临时引用，根运行及其子流可按实际位置消费。等待审批、延迟和重启恢复期间持续保留。根运行及子流全部终结且相关使用释放后进入清理。历史详情可看临时产物曾经的身份和状态。新运行选择持久登记记录，跨运行触发传递已登记产物或其他可独立验证的业务引用。
- 无服务的构建可以登记 `serviceId: null` 的产物，供同项目授权的验证和非部署消费。部署和回滚要求产物明确关联与操作相同的项目服务。需要发布的构建应在产出时绑定 `SERVICE`。为无服务的对象补归属须经过新的授权登记，保留来源及新归属证据。跨服务使用按新的有效生产或分发配置重新确认。变量集合与修订是产出证据。限定来源集合、构建参数或其他条件时，由图的端口规则声明。

## 持久化对象与身份

| 数据对象 | 职责和键 |
| --- | --- |
| `Artifact` | 逻辑产物，按生产运行、节点运行及稳定输出字段区分。记录 `artifactId`、项目、可空服务、输出名称、类型、图版本、流、批次、来源变量集合及修订、创建时间和发起身份。多台构建主机的同一输出归入同一逻辑产物。 |
| `ArtifactInstance` | 逻辑产物在一个确定位置的实例，记录 `instanceId`、`artifactId`、`physicalObjectId`、实际构建位置、目标及工作目录、声明路径、实例状态和最近验证。登记唯一键由节点运行、输出字段、生产目标和同一输出内稳定的实例键组成。 |
| `PhysicalObject` | 实际位置、可验证身份和所有权。多个实例可引用同一实物。位置锁阻止同一地址被同时登记或清理，实物身份用于核对当前对象及聚合使用引用。 |
| 临时产物 | 沿用逻辑产物和实例身份，额外记录所属的根运行。使用与清理均核对作用域和实物身份。 |
| `SourceEvidence` | 关联实际检出的仓库 ID 及名称、ref、分支或 Tag、完整 SHA、构建目录、工作区和生产节点。多来源逐项登记。触发事件及原输入独立记录。无法核验 Git 证据时明确显示来源未知。 |
| `ArtifactUse` 与 `CleanupJob` | 分别记录已发布固定引用、执行计划或保留关系，以及清理的申请人或策略、实物和实例、任务身份、目标结果、失败与重试状态、时间及审计。节点记录实耗的实例，历史使用不改变产物的归属。 |

| 实物类型 | 位置描述 | 身份依据 |
| --- | --- | --- |
| `FILE` | `SERVER_PATH` 或 `BUILDER_PATH`，记录 `serverId` 或 `builderId` 及规范绝对路径 | 普通文件类型、大小和 SHA-256。 |
| `DIRECTORY` | `SERVER_PATH` 或 `BUILDER_PATH`，记录稳定主机或构建器身份及规范绝对路径 | 目录类型与清单 SHA-256。清单对相对路径按 UTF-8 字节顺序排序。目录项记录类型，文件项记录内容摘要，允许保留的目录内链接记录目标并校验边界。读取、传输和验证使用同一版本清单。 |
| `DOCKER_IMAGE` | `DOCKER_ENGINE`，记录稳定 Docker 引擎标识及所属服务器或构建器 | 精确 Image ID 及目标平台。镜像名和 Tag 用于展示和追溯，Tag 移动时仍核对固定 Image ID。 |
| `DOCKER_IMAGE` 的显式分发 | `REGISTRY`，记录 `registryId` 和仓库 | 固定 Digest 和平台。需要时按 Digest 校验接收的镜像。 |

从临时工作区收集文件及目录时，优先在构建主机移动到实例独立的持久位置。跨文件系统时本地复制、校验，再完成登记。只有明确属于该产物的独立持久对象可原位登记为 `MANAGED`。已存在的外部文件、共享镜像或第三方 Registry 对象登记为 `EXTERNAL`。显式分发或归档保留与源实例及接收端身份的关系。管理端持久位置服从同样的定位、所有权与验证规则。首轮 Registry 支持固定 Digest 的引用验证，托管清理由后续 Registry 策略明确。

一次登记在发布输出前完成。Worker 使用稳定的登记键和预留位置核对中断留下的文件、目录或镜像。对象匹配时继续登记，无法确认时记录待处理的原因。实例持久化成功且处于 `ACTIVE` 后才进入独立运行的选择范围。工作区清理走自己的边界，持久实物的生命周期由引用和清理任务决定。

## 应用前验证与清理

1. 验证先按项目、服务、端口类型、冻结目标、来源限制及访问权限解析引用，再在实际位置核对对象。写入、回滚、分发和下载在消费时再次核对。对未来产物，预览保存生产节点、输出字段和目标约束，生产成功后在消费节点执行同样验证。
2. 同机匹配为首轮默认路径。跨主机使用已存在且验证通过的分发实例，或图中明确的分发动作。固定路径或镜像身份发生变化时阻止使用。传输后的接收对象需复核摘要或镜像身份。文件部署落入独立发布位置，保持原产物可复用。
3. 历史选择固定具体实例。显式启用「最新兼容」时按目标与图条件过滤后逐候选核对，给出最终选择和被跳过的较新候选原因。确认后的运行沿用固定选择，变更候选须重新预览及确认。备份恢复后按服务器现状重新验证远端实物。

验证状态为 `NOT_CHECKED`、`AVAILABLE`、`MISSING`、`CHANGED`、`UNVERIFIABLE`。`MISSING` 来自成功连接并确认实物不存在。`CHANGED` 来自类型、内容或对应身份变化。网络、凭据和权限故障保存为 `UNVERIFIABLE`。记录验证时间和可审计原因，实际消费仍按本次检查结果判定。实例生命周期采用 `STAGING`、`ACTIVE`、`CLEANING`、`DELETED`，清理结果独立记录。

- 手动和保留策略共用清理入口。预览列出物理对象、引用及保护原因。策略按平台默认、项目覆盖、服务覆盖解析，支持保留时长和数量。人工固定、已发布且明确固定使用、待执行或审批、活动运行、受保留的回滚版本及正在使用的镜像均参与引用检查。
- 确认使用和申请清理在 SQLite 与 PostgreSQL 采用相同的事务边界与一致的加锁顺序。锁定实例和共享实物身份，计算当前保护关系并写入使用引用或清理任务。任务进入 `CLEANING` 后退出新计划选择。SSH 与镜像操作在数据库事务外执行，Worker 使用稳定任务身份复核和重试。
- 清理前核对目标身份、维序托管归属、当前对象及位置边界。外部引用只解除。存在其他有效实例、使用该镜像的容器或共享标签时保留实物并记录原因。可确认已不存在时视为清理完成。发现位置被替换、对象内容变化时保留原因并进入核查。连接或授权暂时失败时保留可重试状态，多目标只重试未完成实例。
- 每次登记、验证、固定、应用和清理记录发起身份及相应上下文。清理结束后保留产物 ID、生产来源、实物身份快照和处理结果，便于历史运行查询。

## 图内发布、审批与回滚

| 能力 | 冻结及执行规则 |
| --- | --- |
| 发布位置 | 部署节点独立绑定 `SERVICE`、`TARGETS`、`ARTIFACT` 和发布配置。`FILE` 部署接收文件或目录，固定规范发布目录。`COMPOSE` 部署接收镜像，固定 Compose 模板来源、版本和摘要、Compose 项目名及实际 Docker 引擎。启停参数由节点声明。 |
| 发布身份和锁 | 发布及回滚记录使用项目、服务、服务器、部署方式和规范目的地作为稳定身份。文件目的地是实际发布根。Compose 目的地是 Docker 引擎内的项目名。有重叠写入范围时按实际目标位置加锁，跨项目也核对共享位置。切换变量集合时沿用同一身份、锁及回滚历史。 |
| 审核与审批 | 审核节点按实际依赖的每项仓库及 SHA 核对。审批节点关联计划摘要、服务、目标成员、已冻结产物实例及目标位置。图中审核审批发生在新产物产生后时，先绑定产物实际身份再生成审批记录。实质变化提交新计划并重新审批。 |
| 健康检查与回滚 | 健康确认、明确失败和外部结果未知有不同输出。确认失败可进入图中声明的回滚路径。执行结果未知时保存证据并进入 `NEEDS_ATTENTION`。独立回滚流绑定历史发布快照或同一服务可用的历史产物，重新验证目标、产物和权限后执行。 |
| 逐目标结果与历史 | 每台服务器独立保存开始及结束时间、状态、日志、审核及审批关系、实际使用的产物、成功激活的发布记录及回滚关系。确定有成功也有失败时汇总为 `PARTIAL_SUCCESS`，存在未核实写入时汇总为 `NEEDS_ATTENTION`。服务卡片上的近期状态从实际服务与目标聚合。 |

## 接口和演示数据对照

所有接口先校验项目可访问范围，敏感凭据以引用方式使用。管理员可调整保留策略、固定与清理。授权操作员可预览、运行及主动验证产物。观察者读取资源详情、已记录的验证状态和运行历史。

| 接口 | 输入或结果 |
| --- | --- |
| `GET /artifacts` | 按 `projectId`、`serviceId`、`environmentSetId`、`repositoryId`、`ref`、`commitSha`、`serverId`、`kind` 及状态筛选。输入 `limit` 和可选 `cursor`，按创建时间及 ID 稳定分页，返回逻辑产物、实例摘要、生产运行链接与 `nextCursor`。 |
| `GET /artifacts/:id`、`POST /artifacts/:id/verify` | 查询详情，或传可选 `instanceIds` 在授权范围主动验证。返回物理位置、实际来源、逐实例结果和时间。 |
| `PUT /artifact-retention/artifacts/:id/pin` | `{ pinned }`，固定或解除逻辑产物的保留保护。 |
| `POST /artifact-retention/preview`、`POST /artifact-retention/prune` | 预览接收 `artifacts: ArtifactRef[]`，返回位置、影响、保护原因与计划摘要。确认按 `planDigest` 和 `idempotencyKey` 复核实际候选，返回清理任务 ID 与逐实例状态。 |
| 执行图运行预览与详情 | 预览返回选定实例及身份、来源节点、用途和验证结果。运行详情提供 `ARTIFACT`、`SERVICE`、`SERVICE_RESULT` 的类型和实际值，并按目标关联发布及回滚记录。 |

演示定义覆盖无服务或无发布目标的管理端构建、目标端构建同机登记的文件和目录，以及本机固定 Image ID 的镜像。独立部署以 `{ artifactId }` 选择前次同服务的登记结果，在固定目标上确定实例。回滚使用同一目的地的历史产物或发布快照。更换变量集合时，仓库固定 SHA、目标、目的地和已选择实物由各自绑定保持。所有示例对象身份与实际校验结果在后续阶段产生，阶段 0 演示定义用于描述这些关系。
