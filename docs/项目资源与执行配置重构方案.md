# 项目资源与执行配置重构方案

本方案将 2026-11-20 的《维序项目资源与执行配置重构方案》与已确定的四入口工作台合并。项目成员应能从一个服务找到源码、环境和发布目标，运行前看清每个值来自哪里，运行后从产物或发布记录找回生成它的图版本和节点。

## 项目入口与资源边界

| 一级入口 | 主操作与上下文 |
| --- | --- |
| 项目资源（默认） | 顶部摘要提供服务、环境和最近运行，下面按仓库、服务、环境、服务器与分组、访问地址、项目依赖查看。图中选中的资源可跳到详情，详情可返回引用它的流、节点或记录。 |
| 执行图 | 一张项目画布承载多个开始入口。服务的“运行”进入对应发布版开始节点，带入服务和环境；共享节点面板随所选流显示输入来源。 |
| 交付记录 | 按服务、环境、提交查看构建产物、部署与回滚、待审批发布。历史展示当次目标、来源运行、图版本、生产节点和实际消费的制品。 |
| 项目配置 | 同页编辑基本信息、执行默认值、项目公共变量和 AI 策略。展示 AI 生效模式、范围和继承来源，支持管理员覆盖或恢复继承。系统设置负责 Provider、密钥、用途路由和系统默认策略；服务环境维护故障处理开关。 |

服务器、分组、凭据和镜像仓库由平台登记，项目保存或展示授权范围内的引用。项目服务器清单按主机 ID 去重，保留直接引用、分组及成员、旧目标、图中固定服务器或目标绑定的来源。区分草稿、可运行的发布版本和待执行计划；仅在某次运行动态选中的服务器进入运行历史。分组成员变化后，资源页展示当前成员，历史显示原快照。AI 资源选择器显示名称和原有引用，资源被项目使用本身不授予 AI 操作权。

页面 URL 保留资源类型、对象、服务环境、配置分区、筛选及返回的项目视图。兼容 `execution-graph?start=…`、`?run=…`、`?pane=history` 及已有产物、部署、审批地址。刷新、浏览器后退或从图和资源详情往返，应回到同一对象。通过直接地址访问也要校验角色及项目归属。

## 字段归属与生效顺序

| 配置 | 编辑入口与取值规则 | 预览或失败行为 |
| --- | --- | --- |
| 构建位置、并发、工作区根、日志保留 | 系统提供默认，项目可覆盖。构建节点可显式指定执行位置；允许调整并发的运行使用已声明的输入。工作目录相对于选定工作区。 | 显示最终值、作用域和来源版本。管理端仅构建只校验隔离执行环境；目标端构建必须解析构建服务器。 |
| 仓库与检出版本 | 仓库登记克隆地址和凭据，连接后探测远端分支及默认分支。服务仓库关联用于展示与推荐。Git 节点接收同项目且获授权的仓库和分支、Tag 或提交，允许多仓库独立检出。 | 显示每个 Git 节点的实际仓库、ref、固定 SHA 和工作区。URL 可匹配已登记仓库，缺失时由有权限者登记后回填。 |
| 环境与环境文件 | 运行选择、触发映射或入口默认值确定环境。节点显式文件优先，其次使用环境配置路径，最后可探测约定文件；文件属于对应 Git 节点的固定提交。 | 预览列出仓库、SHA、相对路径、来源和是否必需。显式文件缺失或越出工作区时阻止消费；可选探测未命中时标记跳过。 |
| 普通变量与敏感变量 | 同名键由低到高依次取仓库环境文件、项目公共变量、项目环境、服务环境、节点显式绑定。先选择有效来源，再按权限注入。平台保留键由系统提供。 | 显示键、覆盖层和敏感引用状态。预览、图快照、日志不保存或显示敏感明文。仅录入服务环境变量时，可在尚未配置发布目标的情况下保存。 |
| 发布目标及发布配置 | 允许的本次目标选择优先，其次是服务环境覆盖，再次是拟增加的项目环境默认目标。由服务环境管理部署方式、目录、Compose 文件、启停、健康检查、审批及回滚。 | 展示来源、展开成员、并发及失败策略。图中实际参与的部署节点决定本次有无发布；若引入“暂停发布”，应作为跨部署入口统一复核的独立策略。 |
| 构建与制品 | 构建模块维护相对目录、命令、具名产物和必需性。文件、目录记录归档校验值，镜像记录不可变 Digest 或已校验的离线归档。部署模块接收登记过的产物引用。 | 区分已固定的历史 ID 与本次预期产出的节点／字段。本次归档完成后补记实际 ID；构建失败时停在构建阶段。 |
| 源码审核与发布审批 | 源码审核核对产物实际来源提交的有效审核决定，服务环境控制是否必需。发布审批针对本次固定制品及目标的上线请求。 | 两项结果分别展示；产物来源无法核实、审核被撤销、目标或权限变化时，在对应放行点重新检查。 |

例如，在测试和生产都检出同一版本时，预览应分别显示“环境文件 `.env.test`，来自测试环境”和“环境文件 `.env.prod`，来自生产环境”。同页还应显示“镜像来自本流构建节点的 `image` 输出”或“镜像来自开始参数指定的历史制品”。若服务关联的主仓库为 A、实际 Git 输入为 B，预览和产物溯源均记录 B。当前人工审核记录按项目、服务、环境和 SHA 标识，检查节点成功只生成该步骤结果。多仓构建需先确定受审源码集合并将仓库 ID 与实际 SHA 关联到制品，才能判断一次审核覆盖哪些输入。

## 共享节点与运行计划

1. **草稿与发布。** 草稿可保存缺项。开始声明参数，结束声明结果，流通过端点和选定连线定义。字段使用稳定 ID、类型、必填性及单值或多值约束。每条流独立绑定共享节点的输入和结束输出，可取开始参数、固定值、平台上下文或本路径可用的上游结果。发布时固定图和模块版本，检查项目归属、端点、环、普通分叉歧义和每条成功路径的必需数据；错误定位到流、节点和字段。
2. **预览与确认。** 预览与派发共用解析规则。逐个显示值的来源、版本及约束，至少包括代码、构建位置和命令、环境文件、构建与发布各自的目标、制品绑定、代码审核及发布审批。已有制品按“最新兼容”选择时，在预览固定具体 ID；未来产物只固定生产节点、名称、类型和兼容条件。确认绑定计划摘要，配置、分组或来源变化时返回差异并要求重新确认。
3. **执行与交接。** 每次检出分别输出仓库、实际 SHA、ref、提交说明和工作区引用；触发事件另存事件 ID、时间、ref、提交，允许一个事件启动多仓库运行。Shell 和构建只能消费本次授权工作区的相对路径，允许显式传入 `outputDir`。同一构建可登记 `jar`、`static`、`image`；Shell 生成的文件须经登记后交给部署。跨主机及跨运行消费时检查可达性、摘要、服务环境和目标兼容性。
4. **自动运行与恢复。** 手动、Webhook、定时和上游入口使用相同的参数和策略校验。启用自动入口前，每个必填参数都要有映射、默认值或可验证的选择规则。事件提交与实际检出提交分别记录；例如脚本可区分 `VEYOPS_TRIGGER_COMMIT_SHA` 和对应工作区的 `VEYOPS_GIT_COMMIT_SHA`。重复投递与重复确认按幂等键取回原运行。恢复已确认的运行沿用固定版本、目标和制品；结果不确定时进入人工核查。自动交付仍须满足已有隔离、授权和审批条件。

画布保留拖入、复制节点和删除连线的操作。固定审核路径由该流选定的控制连线决定，运行时按参数选择是否审核才使用判断节点。并行汇合等待本次实际参与的分支。结束节点若声明“本次构建产物”，每条可成功结束的路径都须返回本次登记的具名制品；若声明“服务发布结果”，须绑定本服务、本环境实际成功的部署结果，来源可为部署模块或已发布子流。复用节点时，改变一条流的绑定应保留其他流的输入与输出。

## 引用保护与迁移

- **反查与并发。** 资源详情列出引用它的配置、流、版本及待执行计划。发布和资源移除在事务内复核同一资源状态。归档后退出新选择；仍有可运行版本或待执行计划引用时，提示受影响对象，先替换或停用相关配置。仅有已完成历史时保留快照与稳定 ID。派发前复核凭据、服务器和权限。
- **存量映射。** 先盘点无图项目、旧 `START.delivery`、旧部署目标、触发器固定版本及已有产物。按项目唯一键为缺图项目幂等补建草稿。在新草稿把旧构建字段迁到构建模块，部署字段迁到服务环境或部署输入，保留原配对、显式选边与流内绑定。为可解析的旧目标保留来源及当时的展开规则。
- **切换与恢复。** 在相同输入上并列预览旧计划和新计划，比较路径、运行模式、仓库 SHA、变量来源、产物类型及目标。歧义逐项确认后发布新版本并切换入口和触发器；历史版本、进行中运行、审批和制品继续引用原 ID。出现偏差时可停用新入口，按原版本恢复后续运行，避免重复触发。在 SQLite 与 PostgreSQL 各执行升级、重复迁移和切换恢复，核对项目／图唯一性、服务环境、触发绑定、历史与制品数量。

## 首轮验收

使用同一个 Web 服务、测试和生产两个环境、一张发布图及一个固定 Git SHA。四条流共享构建或部署节点，以运行计划、节点输出、制品记录和实际发布结果判定通过。

| 执行入口 | 必须观察到的结果 |
| --- | --- |
| 仅构建 | 管理端无发布目标仍可构建；再用带有生产默认目标的环境验证打包期间无发布目标连接。归档 `jar` 和 `image` 两个具名产物。改为目标端构建且缺少构建服务器时，预览指出缺项。 |
| 审核并构建 | 使用同一构建节点，经选定的审核路径运行；普通直连不能绕过该流固定的审核步骤。生产发布需要代码审核时，绑定其他 SHA 的结果或已撤销的结果均不能放行。 |
| 构建并部署 | 部署节点只取本次构建的 `image`。测试加载 `.env.test`，生产加载 `.env.prod`，展示各自实际目标、目录和审批；构建失败保留原服务。 |
| 仅部署 | 同一部署节点改由开始参数提供兼容的历史镜像。图发布时允许该值待选，运行时必须固定 ID 和 Digest。选错服务、环境、类型或来源目标时拒绝；无需重建。 |

交叉验证三类失败：必填产物只在一条条件分支产生时，发布诊断指出缺值路径；预览后组成员变化或资源停用时，确认应要求复核；两个项目共享主机时，资源反查和 AI 权限均保持项目边界。保留本次与历史产物的生产节点、触发事件与各 SHA、目标快照、审核决定及发布结果，用于复核与回滚。实施阶段见[总体实施计划](需求梳理与实施计划.md#项目工作台整改开发步骤)。
