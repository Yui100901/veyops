# 执行图与运行契约

本契约依据 2026-11-21 修订稿第 4 至 7 节、第 9 节及第 12.1 节。适用于重构后的新库。阶段 0 确定字段、接口及运行语义，后续阶段按 [重构实施计划](项目交付重构实施计划.md)落地。

## 开始参数与配置归属

| 类型 | 参数值 | 解析规则 |
| --- | --- | --- |
| `SERVICE` | `ServiceRef { serviceId }` | 引用同项目可用服务。服务可作为结果归属，关联仓库可以用于界面推荐。实际构建仓库由节点输入确定。 |
| `ENVIRONMENT_SET` | 单个集合 ID | 开始节点 `environmentSet` 为 `{mode:'NONE'}`、`{mode:'FIXED',environmentSetId}` 或 `{mode:'INPUT',fieldId}`。`INPUT` 引用一个同流单值 `ENVIRONMENT_SET` 参数。运行上下文最多解析一个集合，固定其 ID、名称、修订和有效变量。 |
| `TARGETS` | `{ serverIds?, groupIds?, strategy?, maxParallel?, failurePolicy? }` | 由消费者的明确绑定选择平台资源。构建、部署及远程检查各自声明目标端口。预览展开组成员并按服务器 ID 去重。管理端节点只解析管理端构建器或执行器。 |
| `ARTIFACT` | `ArtifactRef { artifactId, instanceId? }` 或执行结果中的 `TemporaryArtifactRef { temporaryArtifactId }` | 已登记产物可由开始参数、固定选择或显式默认规则引用。按实际目标筛选实例，预览固定已存在的实际实例。临时引用只允许在同一根运行及其子流内按上游结果传递。 |

四个类型各自独立校验。同一集合可配合多个服务及节点目标。发布目录、发布方法、Compose 来源和启停参数归部署节点配置。管理端仅构建可省略发布目标。未关联服务的构建结果可登记和追溯。部署与回滚输入必须具备同项目、同服务的实际产物归属及合适的类型和目标。变量集合 ID 和修订记录构建来源，若有集合限制须由图显式声明。

开始参数按稳定字段 ID 提交。手动运行来自已声明的参数字段和默认值。自动运行由规则固定值、事件映射或默认值提供。预览展示这些来源。服务卡片可传已选服务与开始节点作为导航上下文，进入表单时按声明检查并预填。未声明的值不能直接成为运行输入。

## 节点定义、字段与绑定

- 每个项目拥有一个图。草稿保存 `revision`，发布生成不可变图版本及每流编译结果。开始到可达结束的配对确定执行流。画布用开始节点 ID 作为稳定 `flowId`，`startNodeId` 可作为响应和导航的对应字段。共享节点保存模块和端口声明，绑定按流保存。
- 画布上有开始与结束、功能、条件三类。开始面板为「触发器」「环境变量」，结束面板为「最终输出」。条件节点配置判断来源和分支。功能面板为「输入」「执行」「输出」「环境变量」。自定义功能节点可以执行 Shell 并声明自有端口和变量。功能模板提供可编辑的初始动作及配置。模块 ID 和版本定义内置端口，节点按模块允许的范围声明扩展的输入和输出。已声明的仓库、版本等统一在输入面板配置。
- 草稿画布使用 `type: 'FUNCTION'` 和 `operation` 保存功能节点及其动作。系统模板和从空白节点手动选用同一个动作的配置共用相同的字段模型及编译路径。`inputs` 和 `outputs` 保存显式字段，声明动作端口时沿用该端口的稳定 ID 和类型，显示名称、引用名称和输入默认值可以独立编辑。工作区、产物集合和逐目标状态等结构化结果仍由动作产生。
- Shell、构建和检查节点可在 `environmentDefaults` 保存节点固定的普通环境变量。各流可在 `environmentBindings` 覆盖同名键，敏感值使用凭据或变量集合引用。
- 字段使用 `id`、`name`、`referenceName`、`type` 和适用的 `defaultValue`。自定义声明单值必填。开始及结束节点从目录添加内置字段时，保留该项的 `required`、`multiple`、`selection` 和 `source` 等业务约束。例如 Git 版本可选，产物组承载匹配多个目标的引用，本次构建产物输出带 `CURRENT_RUN` 来源要求。引用名称区分大小写，建议采用英文大写与下划线，例如 `ARTIFACT_DIR`。Shell 使用引用名称将自定义输入注入进程，并把同一名称用作结构化输出的键。动作的真实输出在运行时校验。自定义脚本遗漏结果键时可用字段默认值，已提供的值须符合声明类型。
- 各流可以显式指定来源。否则编译器优先选当前路径上最近的同名兼容输出，其次是同名开始参数，候选都缺值时使用节点默认值。同一条路径上出现不可判定先后的同名并行来源时，应在该流指定来源。发布结果固定生产节点和字段 ID。同节点同类端口及同层变量键的重复声明需要修正。

| 绑定 `kind` | 字段与含义 |
| --- | --- |
| `VALUE` | `value` 为按端口类型校验的固定值或项目资源引用。 |
| `INPUT` | `fieldId` 为当前流开始参数的稳定 ID。 |
| `NODE_INPUT` | `fieldId` 为本节点已解析的输入字段，仅用于节点环境绑定。 |
| `OUTPUT` | `nodeId`、`fieldId` 为当前流实际前序节点及输出字段。 |
| `CONTEXT` | `fieldId` 为公开目录里的系统上下文键。触发业务输入先按规则映射到开始字段。 |
| `ENVIRONMENT_KEY` | `key` 为本次入口变量集合中的键，保留值的敏感属性和安全引用。 |
| `CREDENTIAL` | `credentialId` 指向有权使用且类型匹配的凭据，仅注入有权消费敏感值的节点环境。 |
| `FIRST_AVAILABLE` | `sources` 至少一项，按声明顺序解析。来源已确认跳过或可选未产生时继续选择。仍在执行的来源先等待，已提供但无效的值报告错误。所有候选缺值时使用消费端口的 `onMissing`，必填且无有效默认值时报错。 |
| `AS_GIT_REF` | `{refKind:'BRANCH'|'TAG',source}` 将普通文本显式转换成对应的 `GIT_REF`，转换结果继续按仓库和版本校验。 |

每流使用 `inputBindings[nodeId][fieldId]`、`environmentBindings[nodeId][key]` 和 `outputBindings[fieldId]` 保存覆盖与最终输出。顶层绑定可带 `onMissing`。`ERROR` 报缺项，`OMIT` 仅允许在可选字段省略，`USE_DEFAULT` 使用已声明且有效的默认值，`REPOSITORY_DEFAULT` 只用于 Git 版本。文本空串、`false`、`0` 按本类型约束作为已提供的值校验。

## 目录、编译与执行计划

后端目录同时描述模块版本、允许声明的字段和每流可选来源。发布检查按开始及结束节点编译控制 DAG，确定执行边、显式分支和汇合。每条数据关系记录消费节点及字段、生产节点及字段、候选顺序、类型、数量、敏感约束、缺值策略及相关分支。页面读取同一目录作字段提示，发布请求由后端再次校验。

消费节点可引用沿控制路径能够先完成的生产者。引用同级并行支路的结果时先接通明确的汇合或顺序依赖。汇合等待本次选中的分支终态。必填输入和最终输出必须在每种执行到该消费者的路径上有可证明的来源。互斥分支可通过候选绑定提供各自有保证的值。类型、作用域、失效字段及未覆盖路径均阻止发布。合法的变量覆盖和不同节点间可消歧的重名作为提示。

草稿面板按当前流显示显式绑定、同名取值和节点默认值。编译目录确认只有一个兼容且全路径可用的来源时，可以将其保存为该流的显式绑定。缺少可由运行表单提供的值时，可在消费字段处增加开始参数，同时写入该流的 `INPUT` 绑定。工作区、源码、审核和发布结果从适用的生产节点取得。诊断定位到流、节点、字段及已知问题连线，断线和字段变更提供相关流的导航。

编译结果包含流的控制节点及边、模块端口、所有规范化绑定、数据依赖、分支范围、必填覆盖和所需上下文。运行预览在此基础上冻结仓库、实际 SHA、外部执行目标及已存在产物。普通脚本结果、计划中生产的构建产物和检查结果可延期解析。预览以 `DEFERRED` 记录生产节点、字段及约束。运行以当前根运行和已选路径的持久化节点结果填值，未知实物身份在相应消费前重新核对。

## Git 和节点环境

`CHECKOUT` 的 `repository` 必填，接受同项目仓库 ID 或可唯一匹配同项目已登记仓库的 HTTP(S) 克隆地址。可以将该输入的引用名称填写为 `GIT_REPOSITORY_NAME` 并设置默认地址。`version` 为 `GIT_REF {kind:'BRANCH'|'TAG'|'COMMIT',value}`。使用动作内置的选填版本时，未绑定版本按仓库配置的默认分支和远端默认分支解析。显式声明版本字段时须提供兼容来源或默认值。Git 仓库和版本在运行确认前锁定，因此检查开始参数和预览可解析的同名上游输出。非法仓库、分支、Tag 或 SHA 报告具体原因。

`fetchMode` 使用系统枚举 `GIT_FETCH_MODE`。`LATEST`（拉取最新）仅取得固定提交所需的浅层历史，`FULL`（完整拉取）保留该提交的完整历史。可用节点默认值、固定绑定、开始参数或类型匹配的上游字段设置。默认使用 `LATEST`。上游结果尚未产生时，预览标记拉取方式将在运行中确定，同时固定仓库与提交。两种方式都按已确认的 SHA 检出，分支更新后重试仍使用原提交。

按已验证事件提交检出时，事件仓库 ID 必须与实际检出仓库匹配，计划冻结事件携带的 SHA。只映射事件 ref 时，在预览中针对所选仓库解析 ref 并锁定 SHA。显式跨仓库分支映射在消费仓库独立解析。计划同时记录可信触发事件、选定版本和实际检出事实。派发和重试使用已锁定 SHA。

成功检出输出 `source` 和 `workspace`，并通过正式字段投影 `repositoryId`、`repositoryName`、`ref`、`branch`、`tag`、`commitSha`、实际 `version`、实际 `fetchMode` 和可选提交摘要。按分支解析后冻结 SHA 仍保留原分支名。直接选择 Tag 或 SHA 时可无分支字段。输出中的仓库元数据由实际检出结果提供。

`LOAD_ENV` 使用已绑定的固定工作区。执行配置选择显式 `path` 或 `pathRule {key,paths}`，并用 `required` 指定是否必须取得文件。`paths` 将字符串键值对应到仓库内相对路径。路径映射键在文件加载前从入口参数、集合值或图内显式来源解析。要求加载的文件无法读取、缺失或越出工作区时定位到该节点。可选文件缺失时记录跳过。构建、部署及其他需要读取进程变量的节点使用自己的声明。合并优先级从低到高为已绑定的文件、项目公共变量、入口集合、节点环境变量。每键记录生效来源和被覆盖来源。平台保留的 `VEYOPS_*` 由系统维护，用户显式设置时报错，文件中的保留键跳过并提示。

进程使用 `VEYOPS_PROJECT_ID` 和 `VEYOPS_PROJECT_SLUG` 标识当前项目。节点明确关联服务时以该服务提供 `VEYOPS_SERVICE_ID` 和 `VEYOPS_SERVICE_SLUG`，未在节点指定服务时沿用当前流唯一已解析的服务关联。无服务或流级归属有歧义时省略服务变量。`VEYOPS_GIT_COMMIT_SHA` 来自明确的实际检出，触发事件中的 SHA 和 ref 分别保存在触发上下文及其专用变量中。

## 运行接口和持久化边界

| 操作 | 契约 |
| --- | --- |
| 目录、草稿与发布 | `/projects/:id/execution-graph` 下使用 `GET /catalog`、`POST /validate` 和 `POST /publish`。发布核对草稿修订，返回图版本与可定位诊断。 |
| 预览 | `POST /projects/:id/execution-graph/flows/:flowId/preview` 接收 `{version,inputs:{parameters}}`。返回 `configurationHash`、可选差异定位用 `planSections`、安全的已解析输入和节点计划。触发上下文由可信规则处理后附入。 |
| 确认 | 同一流的 `POST /run` 接收同一版本、参数、`expectedConfigurationHash`、`idempotencyKey`，可附 `expectedPlanSections`。服务端再次解析及复核，核对计划摘要。相同项目、操作者和幂等键的同一请求返回原运行，键复用到不同请求时报告冲突。 |
| 运行详情与决定 | `GET /projects/:id/execution-graph/runs/:runId` 按图版本、执行流和节点返回状态。管理员在 `POST /runs/:runId/nodes/:nodeId/decision` 作节点审批决定。取消和重试沿用权限与持久状态。 |

预览摘要基于规范化计划计算。计划包含图版本、入口、参数及来源、可信触发事件、变量集合 ID 与修订、各节点的固定源码、已知变量文件及来源、目标快照和执行方式、实际产物实例或已声明的运行内来源、发布配置和保护步骤。结构内的业务顺序按原计划保留。敏感值以安全引用或受保护的内部快照参与冻结。预览响应和审计只展示脱敏信息。

确认事务同时持久化运行计划、幂等键和受保护的资源引用。组成员、变量集合修订、Git 解析结果、产物可用性或其他有效配置在确认前改变时返回差异并要求重新预览。确认后的执行沿用固定快照，并在派发、审批和写入时复核当前操作者权限、凭据、主机及实物身份。重试沿用原计划和固定 SHA，需要新增目标或替换产物时重新预览。已发布可运行版本和在途计划的引用均与资源归档及产物清理串行校验。

## 输出、发布与异常结果

节点成功前校验并保存声明的输出。输出可以是普通值、结构化值、源码、工作区、变量引用、产物或服务结果。Shell 每个执行单元最多通过一条 `VEYOPS_OUTPUT=` 结果行提交声明的 JSON 对象。结果的键使用输出引用名称，持久化时映射到稳定字段 ID。多条结果行、未知或重复键、超限或非法 JSON、缺必填输出、值类型或敏感约束不符均定位到该执行单元及可确定的输出字段。专用结果行独立解析，日志排除原始结果行并对常规输出应用脱敏。结束节点逐项解析本流最终输出绑定。

文件发布可将登记产物动作的相对路径输入声明为 `ARTIFACT_DIR`，填写 `./dist` 等默认值，也可以从上游取得该路径。登记动作在已持有的工作区内收集实际文件或目录，部署动作消费真实产物引用。目标服务器上的发布目录独立配置。

每个节点运行持久化图版本、流、节点、模块版本及选边结果。按节点和实际目标分别存输入来源、执行位置及任务状态、日志引用、结构化输出及实际注入的变量键和来源。敏感值通过掩码或安全引用追溯。等待、审批、取消和恢复读取同一计划及结果。运行详情按「输入、执行、输出、环境变量」展示，并支持从字段回到来源。

`ServiceRef {serviceId}` 用于 `SERVICE` 端口。`ServiceResult {operation,service,status,targets}` 由真实部署、检查或回滚节点通过 `SERVICE_RESULT` 端口返回，其中 `operation` 为 `DEPLOY`、`CHECK` 或 `ROLLBACK`，`service` 为 `ServiceRef`。逐目标结构使用 `serverId`、`status`、`health`、`consumedArtifacts`，以及适用时的 `deploymentId`、`rollbackOfDeploymentId` 和 `reason`。健康状态为 `NOT_CHECKED`、`HEALTHY`、`UNHEALTHY` 或 `UNKNOWN`。任务 ID 随节点逐目标执行记录保存，通过同一次运行及服务器定位。文件和目录使用 `FILE` 发布，Docker 镜像使用 `COMPOSE` 发布。 [产物与发布契约](重构契约-产物与发布.md)

审核节点核对实际仓库及完整 SHA。审批记录关联当前运行节点、操作者、决定及时间，并绑定固定计划、服务、实际产物实例和目标。审批后有影响写入的变化时重新确认及审批。发布与回滚沿用由项目、服务、实际服务器、部署方式及规范发布位置确定的身份，另按实际服务器及位置检查共享写入冲突。变量集合变化时继续使用同一发布锁、Compose 项目归属及历史记录。

明确的健康失败可以由图的显式分支进入回滚，按原快照及已验证产物执行。SSH 中断等导致写入未知时记为 `NEEDS_ATTENTION`，保存逐目标证据并待核实。部分目标失败只按图声明的策略影响其他目标。部署、检查、回滚和审批的业务结果通过运行详情定位。

## 权限和诊断

- 管理员管理平台资源和凭据，处理源码审核与节点审批。操作员按项目权限维护、发布及运行执行流。观察者读取获授权的图、运行及脱敏结果。确认、自动触发及派发均复核执行身份和资源权限。
- 预览、确认、编译及运行诊断保留现有 `code` 和 `message`，编译问题附 `severity` 区分错误与提示。定位字段包括 `flowId`、`nodeId`、`fieldId`、`parameterId`，也可附 `sourceNodeId`、`sourceFieldId`、`branchId`、`entityType`、`entityId`、`serviceId`、`environmentSetId`、`serverId` 和可安全展示的相关证据。流、节点及字段显示名为界面辅助信息，定位使用稳定 ID。
- 错误响应沿用 HTTP 状态及 `error.planIssue`，展示可知的问题和资源。已提供的错误值、无权限和目标变化各自保留原始类别。计划变化、幂等键冲突和已停用版本形成冲突诊断。发布诊断可列出多个消费端口及分支，运行详情记录每个失败目标的原因。
