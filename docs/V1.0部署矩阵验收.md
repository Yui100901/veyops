## 批量环境初始化验收

2026-11-16 使用提交 `a34b7ac` 启动独立的 VeyOps API、Worker 和 SQLite 实例。五个 Ubuntu 22.04 Docker 容器各自运行 systemd 和 SSH，分别验证主机密钥、注册、探测后加入同一服务器组。镜像预缓存了 APT 软件包，安装前逐台确认 Docker、Node.js、npm 和 Nginx 均未安装。目标预览同时选择分组和组内一台服务器，结果仍为五个目标。

| 内置方案   | 首轮并行，实测峰值 3 | 顺序复跑，实测峰值 1 | 逐目标独立校验                                                           |
| ---------- | -------------------- | -------------------- | ------------------------------------------------------------------------ |
| Docker v1  | 5/5                  | 5/5                  | Docker 29.1.3，systemd 服务启用且运行，本容器 Unix socket 可查询守护进程 |
| Node.js v1 | 5/5                  | 5/5                  | Node.js 12.22.9 可执行脚本，npm 8.5.1 可用                               |
| Nginx v1   | 5/5                  | 5/5                  | Nginx 1.18.0，systemd 服务启用且运行，配置检查通过，HTTP 返回 200        |

六条任务共核对 90 条步骤执行记录和日志，顺序均为前置检查、安装、后置验证。两轮固定使用 v1，复跑后的软件版本、健康结果和各目标的 dpkg 日志一致。故障对照中，首个低权限 SSH 账号的前置检查以退出码 1 失败，该目标跳过安装和后置验证。采用 `CONTINUE` 的顺序任务随后完成五个目标，整体为 `PARTIAL_FAILED`。

Docker 验收使用容器内的 VFS 存储和禁用内层网桥的守护进程配置。一个目标成功加载了 BusyBox 镜像，进一步启动内层容器时被外层容器的 keyring 限制拦截。 [Docker 默认 seccomp 配置](https://docs.docker.com/engine/security/seccomp/)

Node.js 方案使用 Ubuntu 22.04 软件源提供的版本，实测版本低于 VeyOps 所需的 Node.js 22.12。

测试结束后清理了 API 实例、测试容器、镜像、网络和数据目录。测试前运行的 153 个容器在结束快照中均以原 ID 运行，41 项宿主机服务均仍在运行。
