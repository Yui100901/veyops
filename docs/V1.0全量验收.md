## Compose 与现场复核

从基线归档构建了生产 Dockerfile，通过构建参数指定的镜像站取得 Node.js 基础镜像。Compose v2.39.1 上实际运行 SQLite 和 PostgreSQL 17.12 两种组合。两种数据库均在容器重建后保持数据，并分别恢复到新实例。默认工作模式及 `split-worker` 均启动成功。禁用内嵌 Worker 时任务保持排队，单独启动 Worker 后只领取一次并完成 SSH 命令，API 从共享数据卷读取日志。

镜像构建时 npm 输出显示开发依赖有 7 项中危告警，裁剪后生产 npm 依赖的该次扫描为 0 项。显式对禁用健康检查的 Worker 使用 `up --wait` 会被该 Compose 版本拒绝，文档中的 `up -d` 实测通过。

批量初始化使用 Ubuntu 22.04 软件源的 Node.js 12.22.9 / npm 8.5.1。面向该目标的 Node.js 应用需要按其自身版本要求配置工具链。批量测试验证了每个目标的 Docker 服务和本地守护进程 socket。镜像构建和真实容器运行另在闭环 F 验证。

测试实例、临时数据、网络、Registry、Git 仓库和容器均已清理。清理后核对了相关端口和测试资源，并确认各批次快照中的原有运行服务和容器仍在运行。并行验收批次之间的一处容器 ID 变化来自批量测试目标的重建。
