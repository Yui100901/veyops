# VeyOps 项目交付重构实施计划

产品依据为 2026-11-21《维序（VeyOps）产品需求与改造实施计划》修订稿。代码盘点基线为 `c129b2e`。本计划沿用修订稿的 A01–A34 验收编号。开发按下述依赖顺序推进，实机结果记入本页验收记录。

## 本轮重构边界

- **服务呈现应用。** 服务保存身份、仓库关联和有序的多条访问地址。项目工作台为「项目资源、执行图、产物、项目配置」。服务器和分组由平台统一维护，项目通过节点、计划与产物引用并追溯实际服务器。
- **执行图持有交付配置。** 开始节点分别声明服务、变量集合、构建目标、发布目标和产物参数。构建、部署、审核、审批、健康检查及回滚各自通过图声明。变量集合只提供配置值。同一个集合可以用于不同目标，同一目标也可以搭配不同集合。
- **产物引用构建结果。** 目标端文件、目录和镜像默认保留在构建主机。跨主机使用须有已验证的分发来源或图内显式传输。每件产物有生产记录、真实实物身份、所有权与使用关系，配置和运行历史保留其生成时的证据。
- **新模式用空库交付。** SQLite 和 PostgreSQL 使用同一业务关系及事务约束。从新结构初始化，装入同一份演示定义。旧实例的数据处置另行安排。前一轮服务环境默认目标、四入口「交付记录」和旧 Pipeline 迁移不再作为本轮开发主线。

## 先确定的接口和运行规则

1. **独立身份。** `SERVICE`、`ENVIRONMENT_SET`、`TARGETS`、`ARTIFACT` 输入分别校验。一次运行最多选一组变量。服务地址的列表省略表示保留，空列表表示清空。项目和服务的目标默认值改为节点或开始参数的明确绑定。发布与回滚按实际服务、目标和发布位置确定身份，切换变量集合继续使用同一发布锁、Compose 项目标识和回滚历史。 [现有锁键](../apps/api/src/modules/deployments/deployment-lock.ts)
2. **字段与依赖。** 模块内置端口由版本定义，允许扩展的模块才接收用户字段。上游名称按本流、类型和控制顺序检索，保存节点和字段 ID。`FIRST_AVAILABLE` 只在可确认的缺值时继续。未完成的上游要等待，已经提供的无效值直接诊断。节点变量先解析输入再注入，按仓库文件、项目公共变量、入口集合、节点绑定覆盖。保留键、敏感约束、重名及被覆盖来源均可定位。
3. **预览与执行边界。** 仓库、Git SHA、外部目标和已存在产物在确认前解析并固定。运行中产生的值在计划中记录生产节点与约束。按事件提交检出要核对事件仓库，按 ref 触发则固定该仓库本次解析的 SHA。Git 版本未提供时按端口缺值策略处理，优先使用显式配置的默认分支，其次使用探测到的远端默认分支。显式版本无效时报告错误。 [现有仓库解析](../apps/api/src/modules/projects/repository-metadata.service.ts)
4. **产物的使用边界。** 区分本次运行临时输出、维序托管的持久实物和外部引用。文件和目录分别识别类型及内容摘要，镜像以 Docker 主机、Image ID 和平台确定。产物的变量集合和修订用于记录来源。历史应用以项目、服务、类型、目标及图中明确的来源约束核对，变量集合名称自身不限定适用范围。
5. **写入保护。** 预览、确认、派发、审核、审批和实际写入各核对本阶段需要的权限与快照。申请清理和确认使用共享引用检查，清理锁定实物身份。验证可区分可用、不存在、内容变化和无法验证。未知的外部写入结果进入待核查，明确健康失败才走已配置的回滚分支。

### 工作台和变量集合的实现

1. 迁移 `028_service_addresses` 建立服务地址和修订，迁移 `029_project_environment_sets` 建立集合和变量项。服务、变量集合和图分别保留稳定标识。 [服务地址](../apps/api/src/modules/projects/service-addresses.ts) [变量集合](../apps/api/src/modules/projects/environment-sets.service.ts)
2. 执行图确认前复核集合修订和凭据版本。已确认的运行及其预览已解析的子流使用冻结的配置。加载文件的固定来源和覆盖关系可从预览和运行详情追溯。现有交付引擎的数据库外键过渡使用固定的项目级内部标识，与用户选择的变量集合独立。 [图运行](../apps/api/src/modules/execution-graphs/graph-runner.service.ts)
3. 演示定义覆盖固定 SHA 的多地址服务、两组集合和两组目标。初始化器在专用验收实例内置入资源并发布同一份图定义。 [演示配置](../examples/refactor-stage0/project.yaml)

### 节点运行的实现

1. 草稿目录返回每流的消费端口及可选来源。发布版本保存解析后的端口、绑定和数据依赖。节点与字段保持稳定 ID，引用名和输出名可用于查找。 [发布编译](../apps/api/src/modules/execution-graphs/graph-binding-validation.ts)
2. Git 预览解析分支、Tag 或完整 SHA，省略版本时使用仓库远端默认分支。事件提交需要匹配检出仓库，事件 ref 在消费仓库解析。手动、认证 API、Webhook、Cron 和上游规则复用开始参数与同一套预览确认。 [Git 固定版本](../apps/api/src/modules/projects/repository-metadata.service.ts)
3. 迁移 `030_graph_node_evidence` 保存实际输入、环境绑定、最终输出及定位错误。脚本逐目标解析 `VEYOPS_OUTPUT=` 结果，过程日志继续脱敏。仍启用的历史版本可在版本详情按其原定义运行。 [节点证据与派发](../apps/api/src/modules/execution-graphs/graph-runner.service.ts)

### 产物实物和清理的实现

1. 迁移 `031_artifact_physical_instances` 记录逻辑产物、逐目标实例、可验证实物和临时运行范围。构建工作区内的文件和目录在原机保存至受管位置，镜像记录 Docker 引擎、固定 Image ID 和平台。显式 Registry 分发以 Digest 验证。 [实物适配](../apps/api/src/modules/artifacts/artifact-physical.service.ts)
2. 部署预览固定实例，执行前再次核对原件。目标端同机发布从独立归档副本准备候选版本。管理端到目标端沿用带摘要的归档分发。项目无服务构建可登记产物，发布使用明确的服务归属。 [产物校验与消费](../apps/api/src/modules/artifacts/artifacts.service.ts)
3. 迁移 `032_artifact_cleanup_jobs` 保存清理任务和逐实例结果。确认在事务内复核保护关系并预留实物，Worker 复核所有权后处理，失败实例可重试。外部或仍被引用的实物按保留原因处理。 [清理任务](../apps/api/src/modules/artifacts/artifact-cleanup.service.ts)

### 图内交付的实现

1. 文件部署和 Compose 发布读取图的明确绑定。仓库 Compose 模板按完整 SHA、路径和摘要验证，归档模板按产物校验。发布、健康检查与回滚共享活动发布身份和目标端锁。 [图运行](../apps/api/src/modules/execution-graphs/graph-runner.service.ts) [发布执行](../apps/api/src/modules/pipelines/pipeline-executor.service.ts)
2. 源码审核绑定实际使用的仓库和提交，产物审核覆盖其源码清单。发布审批绑定产物实例及指纹、目标成员与关联服务。计划或身份变化时暂停发布，需重新确认。健康未知标记待处理，已确认不健康可进入人工批准或图中配置的回滚分支。 [审核与审批证据](../apps/api/src/modules/execution-graphs/graph-release-gates.ts)
3. AI 先预览已发布图，人工确认后按同一摘要提交运行，范围与角色在确认时重新核对。归档、发布和回滚的实际证据仍从图运行与产物记录定位。五类流程可从画布预设创建。 [图运行提案](../apps/api/src/modules/ai/ai-graph-actions.service.ts) [预设与示例](../examples/refactor-stage0/README.md)
4. 发布历史、回滚查询和产物清理共用活动发布身份，区分同一服务同一服务器的多个发布目录或 Compose 项目。明确不健康的探针退出码为 `10`，执行故障进入待核查。逐目标核查从运行详情发起，保存外部观测与审计；需要执行发布时重新走预览和确认。 [发布范围](../apps/api/src/modules/deployments/deployment-scope.ts) [逐目标核查](../apps/api/src/modules/execution-graphs/graph-release-inspection.service.ts)
5. 构建节点可将检出的 SHA 等上游值注入进程环境，已知输入随计划固定，运行时再解析等待上游的值。构建前审核可关联一个构建节点，覆盖主仓、依赖仓及异仓变量文件。证据绑定本次节点，Worker 在执行前复核实际仓库及提交。A13、A18、A32 随候选版本验收。 [构建运行](../apps/api/src/modules/execution-graphs/graph-runner.service.ts) [源码审核](../apps/api/src/modules/execution-graphs/graph-release-gates.ts)

候选使用带完整提交标签的运行镜像。Linux 脚本从该提交读取演示、初始化器及验收驱动，分别准备 SQLite 或 PostgreSQL 空库，并保存候选镜像、图版本、产物与发布记录。 [候选操作](../examples/refactor-stage0/README.md#linux-候选验收)
