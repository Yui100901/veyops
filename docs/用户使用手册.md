# VeyOps 用户使用手册

本手册适用于当前以项目执行图组织构建、部署和触发器的版本。可以先按「文件发布入门」完成一次手动交付，再按需配置 Compose 和自动触发。

## 1. 登录与工作台

打开管理员提供的 VeyOps 地址。首次初始化使用 `root` 登录。如果部署时通过 `ADMIN_PASSWORD` 设置了 12–256 个字符的初始密码，使用该密码。配置留空时，从首次启动的控制台输出获取随机密码。首次登录可修改密码，也可点击「跳过并进入工作台」，稍后从账号菜单修改。重启应用会沿用数据库中的账号和密码。安装命令、环境变量及镜像部署方式见 [发布与安装](RELEASES.md)。

管理员在「平台管理 → 系统设置 → 用户管理」创建账号或重置临时密码。新建账号和被重置的账号首次登录需更换临时密码。运维人员可按权限执行已配置的流程，只读用户可查看资源和运行记录。

| 入口 | 用途 |
| --- | --- |
| 服务门户 | 按项目、标签或异常状态查找服务，打开或复制完整的服务地址，查看当前版本和最近发布尝试 |
| 项目发布 | 新建项目，进入项目资源、执行图、产物和项目配置，或从项目卡片运行已发布的执行流 |
| 运维命令 | 执行临时命令、命令模板和运维方案 |
| 任务中心 | 查看执行流与运维任务，追踪状态和日志 |
| 服务器 | 接入 SSH 目标，查看连接检测、部署记录和自动执行授权 |
| 平台管理 | 管理凭据、系统设置、用户、备份和可选 AI 设置 |

页面顶部显示当前位置。点击「工作空间」返回服务门户，点击「项目发布」返回项目列表。进入项目详情和运行记录后，可以点击路径中的项目名称、执行图或运行记录逐级返回。

## 2. 接入一台执行服务器

1. 在「平台管理 → 凭据中心」新增 SSH 密码或 SSH 私钥凭据。使用私钥时，将对应公钥安装到目标服务器的登录账号中。使用专门的执行账号，授予该项目所需的目录及命令权限。
2. 在「服务器」打开接入表单，填写「服务器名称」「主机地址」「SSH 端口」「登录用户名」，并选择 SSH 凭据。
3. 点击「探测 SSH 指纹」。将结果与服务器控制台或可信记录核对。若目标使用 Ed25519 主机密钥，可在其控制台用 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256` 查看指纹。勾选「确认接受此主机指纹」，再点「保存并验证登录」。
4. 确认连接正常，且 SSH 用户能写入工作根目录。文件及目录交付使用 Linux 常用工具，例如 Git、GNU coreutils、`flock` 和 `tar`。Dockerfile 构建和 Compose 发布还需 Docker、Compose 插件，以及该 SSH 用户访问 Docker 守护进程的权限。私有仓库的地址须能从 VeyOps 和执行服务器访问。

每个开始节点选择一台「执行服务器」。一次运行的检出、构建、脚本和发布使用该服务器。发布设置关联项目服务，服务的访问地址仅用于导航。

系统工作根默认为 `~/.veyops/workspace`，其中 `~` 是执行服务器上 SSH 账号的主目录。项目 `file-demo` 的工作目录为 `~/.veyops/workspace/file-demo`，每次运行在其下创建独立的执行 ID 目录。「项目配置 → 项目执行设置」可覆盖「目标端工作根目录」和日志保留天数。

「平台管理 → 系统设置 → 执行与日志」中的「单台服务器任务并发」默认为 10。执行流、运维命令和交互会话在同一台服务器上共享槽位。例如设为 2，服务器 A 正在执行一条流和一个运维命令时，A 的后续任务按提交顺序等候。服务器 B 和 C 可按各自的限额同时执行。等待审批的执行流仍占用一个槽位。同一批运维命令还可指定顺序执行或限制一次并行的目标数量。

## 3. 准备项目、仓库和变量

1. 在「项目发布」点击「新建项目」，填写名称与「唯一标识」。示例使用 `file-demo`，标识用小写字母、数字和连字符。
2. 进入「项目资源 → 仓库 → 添加仓库」。输入 HTTP(S) 克隆地址，例如 `https://git.example.com/team/file-demo.git`。Gitea 仓库可将「代码托管平台」选为 Gitea。私有仓库在凭据中心登记具备读取权限的「Git Token」或「Git 账号密码」，再为仓库选择该凭据。保存后打开仓库详情，核对远程分支和提交。
3. 在「项目资源 → 服务 → 添加服务」登记服务。若已有可访问的页面，在「访问地址」点「添加地址」，填写名称和完整 URL。项目卡片和服务门户会显示名称及完整地址，并提供打开、复制操作。填写 URL 不会创建监听端口或配置代理。
4. 在「项目配置 → 项目公共变量」录入项目共用值。需要测试、生产等差异配置时，在「项目资源 → 变量集合」创建相应集合，并在开始节点选择该集合。

构建和脚本的变量按以下顺序覆盖，同名键以更靠右的配置为准。

```text
仓库 dotenv 文件 → 项目公共变量 → 变量集合 → 开始节点变量
```

变量的表格和 `.env` 文本编辑模式使用同一份数据。批量粘贴时可用 `# @secret KEY` 标记敏感变量。隐藏值时保留界面显示的占位内容可沿用原敏感值。开始节点需要直接引用敏感变量时，选「使用敏感凭据」。避免将真实密钥写入仓库、构建命令和 Compose 文件。

脚本可通过 `$VEYOPS_PROJECT_ID` 读取项目 ID，通过 `$VEYOPS_WORKSPACE` 读取本次工作区，已关联服务的流程还可读取 `$VEYOPS_SERVICE_ID`。检出来源已解析时，`$VEYOPS_GIT_COMMIT_SHA` 提供主源码的提交 SHA。

## 4. 文件发布入门

准备一个名为 `file-demo.git` 的仓库，在 `main` 分支的仓库根提交一个 `index.html`。先完成第 2、3 节的服务器、项目、仓库和服务配置。

1. 进入「项目发布 → 文件发布示例 → 执行图 → 编辑草稿」。新项目预置「最小构建并部署」，包含「构建并部署」「仅构建」「仅部署」三个开始节点。「添加执行流」可以将另一套模板追加到画布。
2. 选中「构建并部署」。填写「执行服务器」，在「源码」添加已登记的仓库，将「Git 版本」选择为分支 `main`。在「发布设置 → 项目服务」选中示例服务，「交付产物来源」选「本次构建产物」。
3. 点击「复制配置到其他入口」。核对复制预览后，确保「仅构建」有同一执行服务器、源码和「产物归属服务」，「仅部署」有执行服务器、项目服务及「运行时选择已有产物」。纯构建产物关联服务后，才能在该服务的仅部署入口选择。
4. 点击共享「构建」节点，将「工作目录」设为 `file-demo`，在「构建命令」填写以下命令。「安装命令」可留空。

   ```sh
   set -eu
   mkdir -p dist
   cp index.html dist/index.html
   ```

5. 在部署节点选择「文件发布」。这个示例只分发文件，停用旧版本和启动新版本命令均可留空。对于需要启动进程的应用，在相应命令中先进入项目产物的目录，例如 `cd file-demo/dist`，再执行该服务实际的停止、启动脚本。首次发布时平台没有可停止的当前版本。
6. 留用结束节点的「保留整个执行目录」。点击「保存并检查发布」，按检查结果定位并补齐缺失项，然后点击「确认发布」。只想保存编辑时，选择「保存草稿」。
7. 切到「运行执行流」，点选「构建并部署」开始节点，点击「预览运行」。核对版本、服务器、提交 SHA 和服务，点击「确认启动」。接着在「运行记录」打开该次执行，检查部署节点的发布路径和结果。

检出目录取克隆地址末段并移除 `.git`，因此示例活动发布目录中包含 `current/file-demo/dist/index.html`。文件发布会切换版本并更新 `current`。如果需要在浏览器访问此文件，需单独配置 Web 服务，把站点根指向活动版本中的对应目录。

可继续用「仅构建」登记一次目录产物，再从「仅部署」的运行参数选择这份产物，核对预览中的产物实例和原始提交。构建失败时，该次运行不会进入后续部署。

### 使用 AI 生成执行图

1. 管理员在「平台管理 → 系统设置 → AI 模型连接」启用模型，并确认仓库分析使用的模型连接可达。
2. 在「执行图 → 编辑草稿」选中一个开始节点。在「源码」选择当前项目登记的仓库、分支、标签或提交。配置后即可展开「AI 辅助构建执行图」。想生成部署节点时，在原开始节点关联项目服务。
3. 如有额外要求，写明构建方式、包管理器或环境。点击「分析仓库并生成建议」。平台按固定提交读取部署说明、构建配置及源码入口。对多仓库节点，可从当前配置中选择要分析的一个仓库。
4. 检查建议显示的提交、文件、命令和节点。点击「添加到草稿」会追加一条新执行流，也可直接放弃。新流程会沿用原开始节点已设的执行服务器和变量。请核对新节点配置，再保存和发布。

## 5. 一个仓库并行构建并发布两个镜像

以下示例使用 `dual-demo.git` 的 `main` 分支和一台 Docker 执行服务器。先登记仓库和项目服务，例如「双组件示例」。仓库使用以下结构。

```text
dual-demo/
  frontend/
    Dockerfile
    index.html
  backend/
    Dockerfile
    cgi-bin/
      health
  compose.yaml
```

`frontend/index.html` 可包含 `<main>VeyOps frontend</main>`。前端 Dockerfile 如下。

```dockerfile
FROM busybox:1.36
WORKDIR /site
COPY index.html .
CMD ["httpd", "-f", "-p", "8080", "-h", "/site"]
```

`backend/cgi-bin/health` 内容如下。将脚本以 LF 行尾提交。

```sh
#!/bin/sh
printf 'Content-Type: application/json\r\n\r\n{"status":"ok"}\n'
```

后端 Dockerfile 如下。确保执行服务器可以取得基础镜像。

```dockerfile
FROM busybox:1.36
WORKDIR /app
COPY cgi-bin/ cgi-bin/
RUN chmod 0755 cgi-bin/health
CMD ["httpd", "-f", "-p", "8080", "-h", "/app"]
```

在「编辑草稿」中组装下图。可以复用已有模板的节点。点击或拖动「节点库」中的节点即可添加，「并行分支」「汇合」位于「更多节点 → 流程控制」。点上游节点输出连接点，再点下游节点输入连接点。右键节点可复制或删除，右键普通连线可断开。

```text
开始 → 代码拉取 → 并行分支 → 前端构建 ─┐
                          └→ 后端构建 ─┴→ 汇合 → Compose 部署 → 结束
```

1. 连线后，在开始节点选择「对应结束节点」。若项目预置模板里还有暂不使用的执行流，补齐那些入口的发布校验项，或在草稿中移除对应开始节点。选中开始节点可查看归属范围，共用节点仍可能被其他开始节点使用。
2. 在开始节点添加 `dual-demo` 仓库和 `main`，选择唯一执行服务器。在两个构建节点分别设置「工作目录」为 `dual-demo/frontend` 和 `dual-demo/backend`，开启「使用 Dockerfile 构建镜像」，「Dockerfile 路径」均填写 `Dockerfile`。两个工作目录各自独立。
3. 在部署节点将「发布方式」改为「Docker Compose」。在结束节点「Docker 镜像登记」添加两个条目，例如 `demo/frontend`、`demo/backend`。来源均选「内置 Dockerfile 构建」，在「构建节点」分别选择前端与后端。可将「发布结果核对」设为「所有目标均已激活」。
4. 回到开始节点，关联项目服务。在「本次发布镜像」勾选两个登记项。分别记下界面在两项旁显示的完整变量名，界面生成的标识以实际显示为准。将下面模板中的两个占位引用替换为实际引用，提交到 `main`。已创建的镜像登记项可保留，以便后续继续使用相同引用。

   ```yaml
   services:
     frontend:
       image: "${VEYOPS_IMAGE_FRONTEND_PLACEHOLDER}"
       healthcheck:
         test: ["CMD-SHELL", "wget -q -O - http://127.0.0.1:8080/ | grep -q frontend"]
         interval: 2s
         timeout: 2s
         retries: 10
     backend:
       image: "${VEYOPS_IMAGE_BACKEND_PLACEHOLDER}"
       healthcheck:
         test: ["CMD-SHELL", "wget -q -O - http://127.0.0.1:8080/cgi-bin/health | grep -q ok"]
         interval: 2s
         timeout: 2s
         retries: 10
   ```

5. 在开始节点选择「Compose 配置来源 → 本次工作区」，「工作区内 Compose 相对路径」填写 `dual-demo/compose.yaml`。「交付产物来源」使用「本次构建产物」。若改用仓库固定提交来源，相对路径从仓库根算起，此例填写 `compose.yaml`。
6. 保存、检查并发布。进入「运行执行流」，预览确认后启动。在运行记录分别查看两个构建节点，核对实际构建区间及镜像 ID，再查看汇合节点和部署结果。在项目的「产物」查看各自登记的镜像。

示例的两个服务使用 Compose 内部端口。若要对外提供访问，按现场地址和空闲端口在 Compose 配置端口映射，再把实际地址录入项目服务。「所有目标均已激活」核对发布结果。若需要把应用健康作为执行流的完成条件，在部署后添加「发布健康检查」，填写检查命令，再将结束节点改为「所有目标均已激活且健康」。例如后端映射到执行服务器的 `127.0.0.1:18081` 时，可用 `curl -fsS http://127.0.0.1:18081/cgi-bin/health` 检查。

单镜像模板使用 `${VEYOPS_IMAGE}`。多镜像发布时，各 Compose 服务都要引用开始节点选中的镜像变量，选中的镜像也都需要在模板中使用。发布记录显示实际激活的各镜像和对应 Image ID。要从源码复现本示例的旧版本，可在「Git 版本」选择「提交 SHA」，填入原记录中的完整提交，重新发布图并预览运行。历史产物选择器当前只接受单个实例，适用于目录和单镜像交付。

## 6. 配置自动触发

触发规则配置在对应开始节点的「触发器管理」中。先发布可以手动运行的图版本，再添加规则。也可先保存停用的规则草稿，待图发布后启用。管理员使用「预检」了解有效配置，再点击「预检并启用」。启用后可以分别查看规则、事件和实际运行。

对需要构建、部署或执行脚本的流程，部署管理员须在 API 和 Worker 的环境中放行对应触发类型，例如 `VEYOPS_AUTO_DELIVERY_TRIGGERS=WEBHOOK,CRON,UPSTREAM`。使用仓库的 Docker Compose 自部署时，可在 `.env` 配置此项并重建 VeyOps 容器，使环境配置生效。管理员打开所选服务器详情，在「执行流自动执行」点「授权自动执行」。更换 SSH 凭据或主机身份后重新核对授权状态。

自动触发沿用入口的已发布配置，包括目标服务器、项目服务、产物来源及审批节点。「构建并部署」入口收到匹配事件后会继续部署。「仅构建」入口只构建和留档。

### Git 推送 Webhook

1. 在开始节点的「源码」先选择要跟踪的仓库和分支。打开「添加触发规则」，填写规则名称，将「触发方式」选为「Git 推送 Webhook」，协议选「Gitea 原生签名」，「源码来源」选该仓库的对应分支。
2. 点击「预检并启用」，打开此规则的「Webhook 投递配置」。确认「接收方服务地址」是 **Gitea 服务可达**的 VeyOps 站点地址。复制「Webhook 投递地址」和只在生成时显示的「本次令牌」。
3. 打开对应 Gitea 仓库的「设置 → Webhooks」，新增 Gitea 类型的 Webhook。将正式地址填入 Target URL，内容类型选 JSON，Secret 填刚复制的令牌，勾选 Push 事件并启用。
4. 向规则匹配的分支推送一个新提交。回到 VeyOps 查看已接收事件并打开对应运行，核对检出的完整 SHA 与推送一致。Gitea 投递历史可用于核对请求是否抵达。

需要只检查签名和连通性时，可临时用规则详情「测试接收」中的「接收验证地址」替换 Gitea 的 Target URL。验证完成后换回正式地址。令牌遗失可从规则详情「轮换令牌」，轮换后同时更新 Gitea 的 Secret。

### 仓库轮询与定时

1. 在对应开始节点添加规则，触发方式选「仓库有更新时构建」。
2. 选择「源码来源」。填写五字段 Cron 表达式，例如 `*/5 * * * *` 每 5 分钟检查一次，时区可设为 `Asia/Shanghai`。
3. 默认第一次检查只记录分支的当前提交。若要首次检查就运行，勾选「首次检查立即构建」。
4. 「预检并启用」后，查看生效的仓库和分支、最近检查及观测提交。第一次检查完成后再推送，下一轮检测到变化会按该 SHA 运行。需要每到计划时间都执行时，可选「定时构建」。

Webhooks 和轮询可配置给同一执行流。两者发现同一仓库和分支的同一次源码变化时，事件可指向同一条运行记录。

### 同项目上游成功触发

1. 在同一项目中发布两条已配对的执行流「构建 A」和「构建 B」。每条从自己的开始节点到对应的结束节点，可分别选择执行服务器。
2. 点「构建 B」的开始节点，添加规则「A 成功后运行 B」。将触发方式选为「上游执行流完成后运行」，「上游执行流」选「构建 A」，「完成条件」选「上游成功」。
3. 预检启用后，画布会用紫色虚线箭头从 A 的结束节点指向 B 的开始节点。修改关系或暂停规则时打开 B 的「触发器管理」。
4. 手动运行 A，或给 A 配置推送触发。在 A 成功后，到 B 的触发事件中查看上游运行 ID 并打开 B 的运行记录。

若 B 是发布入口并要使用 A 的产物，可将 A 的产物登记为持久产物并关联服务，将 B 的「交付产物来源」设为「上游成功运行的产物」，按需选择登记名称。跨服务器消费时，先确认产物可分发且能在 B 的服务器上使用。目标端本地镜像留在原 Docker 主机，跨服务器镜像应使用目标可访问的 Registry 固定 Digest。

## 7. 查运行、产物和回滚

- 在「任务中心」打开某条执行流任务，或从项目的「执行图 → 运行记录」打开同一次运行。两处共用详情。「查看全部」汇总节点状态与日志。「分节点查看」可通过画布或「定位节点」查阅单个节点的详细日志、源码和产物。运行画布按本次执行路径排列。
- 遇到等待审批，在运行详情核对固定产物、提交和执行目标，使用有权限的账号处理审批。
- 在「产物」核对产物类型、校验、来源运行和服务器，按页面可用操作验证或下载。活跃发布引用的产物受保护，先核对当前服务版本和保留要求再清理。
- 在服务详情对照「当前版本」和「最近尝试」。一次新发布失败时，打开该次运行的失败节点和目标详情，核对当前实际状态。
- 需要回滚时，为该项目建立一条独立的「按产物回滚」执行流。开始节点选择原发布服务器、原项目服务和曾成功发布的兼容产物，在部署前配置发布审批，按需要加入发布健康检查。保存发布后重新预览，确认当前版本与历史产物后启动并审批。回滚配置详见 [执行流交付](执行流交付.md)。

## 8. 运维命令、AI 与交互输入

1. 打开「运维命令」，选择服务器或分组。普通命令填写脚本后先预览，核对目标再确认执行。每个目标按所在服务器的共享队列等待。
2. 点击「AI 运维助手」，可以问「请分别查询所选服务器的磁盘占用」。助手只检查选中的服务器。「请为所选目标安装 Docker」会生成待确认提案，审核目标和操作内容后可确认或拒绝。
3. 需要根据远端输出继续输入时，勾选「启用交互模式」，输入初始命令或使用交互 Shell，再预览并启动。在任务详情的「交互输入」里发送一行或多行文本，可以发送给所有正在运行的目标，也可以只勾选部分目标。各目标的输出都记入该任务日志。目标退出后不再接收输入。需要结束仍在运行的会话时，可取消任务。

## 9. 常见问题

| 现象 | 排查方法 |
| --- | --- |
| 服务器下拉中找不到目标 | 检查服务器记录与凭据是否启用，主机指纹是否已确认，SSH 用户是否能登录 |
| 选择不到结束节点 | 检查开始节点到结束节点的有向路径，补齐断开的普通连线 |
| 预览没有当前分支 | 核对仓库的 HTTP(S) 克隆地址、读取凭据和分支缓存，按需刷新仓库分支 |
| 检出失败 | 先看检出节点实际 SHA 和 SSH 日志，确认执行服务器上有 Git，且能访问该仓库 |
| 构建命令找不到或依赖下载失败 | 在所选服务器检查相同 SSH 用户的 PATH、依赖工具和出站网络。确认安装命令和构建目录后重新发布并运行 |
| Compose 变量缺失或镜像不匹配 | 核对开始节点所选镜像、结束节点的构建关联及 Compose 的 `image` 引用。若缺少基础镜像，检查目标端拉取权限、网络和镜像名 |
| 部署提示端口占用 | 从部署节点日志定位端口和服务，检查服务器上现有监听者，选择空闲端口或使用已有的发布切换方式 |
| Webhook 收不到事件 | 从 Gitea 投递历史核对连通性、HTTP 状态和是否使用正式地址。再检查签名密钥、事件类型、分支、规则启用状态及目标服务器授权 |
| 轮询首次检查没有运行 | 检查按计划是否完成首轮观测、分支是否有新提交，以及是否勾选「首次检查立即构建」 |
| 工作区或产物不可用 | 从产物记录核对实际服务器、可用状态和校验结果。目录移动、删除或镜像标签被改写时，按相同提交重新构建并登记 |
| 很久仍在队列中 | 查看所选服务器是否有活动运行或待审批，检查系统并发限额及 Worker 状态 |
| 运行显示待核查 | 对照发布节点、服务器和服务当前版本，确认上次动作的实际结果后再发起新运行 |
