# AI 配置、工具与执行权限

AI 使用 OpenAI 兼容的 `POST {baseUrl}/chat/completions`，可不配置。未配置或 Provider 被禁用时，资源管理、执行图与手工运维继续运行，聊天会给出明确提示。

## Provider

管理员在系统设置中配置名称、Base URL、模型、API Key 和超时。Base URL 可以是 `https://api.deepseek.com` 或带 `/v1` 的兼容端点。模型名按配置原样发送。

API Key 由统一凭据服务用 AES-256-GCM 加密，Provider 只保存凭据引用。列表、编辑与测试响应不回显密钥；留空编辑密钥表示保留当前凭据。可禁用 Provider，也可引用现有启用的 `API_KEY` 类型凭据。生产使用 HTTPS；仅本机测试可使用 HTTP。HTTP 重定向不跟随，避免向重定向站点发送密钥。

DeepSeek 端点请求带 `thinking:{type:"disabled"}`，普通兼容 Provider 不附加该扩展参数。模型返回的推理字段不会展示或持久化。原始上游错误正文不回传，连接、超时与 HTTP 错误返回安全摘要。

### 按用途路由

在「系统设置 → 模型路由」分别选择助手对话、仓库分析、任务诊断的默认连接。仓库页面对话使用仓库路由，任务页面对话使用诊断路由。对话中手动选择的模型优先。独立的仓库分析工具按仓库路由发送仓库证据，交付结果分析和故障诊断按诊断路由发送摘要。用途未配置时，系统使用最早创建且凭据有效的启用连接。指定的连接失效时，需要管理员修复或重设该路由。

`GET /ai/routing` 返回默认模型映射。管理员通过 `PUT /ai/routing` 整体替换映射，可用字段是 `chat`、`repository`、`diagnosis`，值为 Provider ID。省略字段恢复该用途的默认选择。

### 条件写操作策略

在系统或项目的「AI 执行权限 → 操作规则」添加条件限制。同一条规则中的条件须同时满足，批量操作包含所选服务器即匹配；目标数按去重后的服务器计算。仓库写操作可按角色限制。命中任一系统或项目禁止规则时，整批拒绝。命中强制确认规则时，用户须审批提案。历史提案确认时重新计算当前规则。

例如，下列 `actionRules` 在管理员调用初始化组件时对两台及以上目标要求确认，并禁止运维人员创建评审 PR。将该数组随 `mode` 提交给 `PATCH /ai/policies`。传入空数组可删除当前策略的全部条件规则。

```json
[
  { "action": "initialize_component", "role": "ADMIN", "minimumTargets": 2, "effect": "CONFIRM" },
  { "action": "open_pull_request", "role": "OPERATOR", "effect": "DENY" }
]
```

## 项目与页面权限

系统设置管理模型连接和默认权限。管理员在项目的 AI 权限页可以覆盖默认策略，也可以恢复继承。系统限定的项目、服务器、仓库和禁止操作继续生效。仓库、服务、失败任务及运维方案页面可直接打开助手。页面负责选定资源，后端在每轮对话中重新核对资源归属和执行权限。查看某个历史运维方案版本时，助手读取所选版本的名称和步骤。

## 服务环境的故障处理

管理员在服务的环境配置中开启故障处理。默认关闭，每个环境独立设置。开启后可仅收集诊断，或指定允许修复的一种组件。打开失败任务可以查看故障分类、模型建议、待审批提案、修复任务及其验证日志。

Worker 从失败任务中提取阶段、退出码和固定故障分类。下载失败、端口占用及库依赖问题先给出核查建议。对于目标端缺少已指定组件的故障，只有原目标唯一、仍与当前配置一致且 SSH 巡检证实缺失时，才允许发起内置安装方案。只读模式保留建议，交互模式由原任务发起人审批，完全控制模式在当前授权允许时自动执行。安装与验证使用固定方案版本，模型输出的文字仅用于说明。

每次失败最多触发一次修复。修复任务所有步骤成功时记为 `VERIFIED`，用户可从原执行流重新预览并运行以验证业务结果。模型不可用、执行超时、目标状态不明或验证失败的记录转为人工处理。故障处理开关、提案审批和修复步骤都写入审计。

## 业务工具

| 工具                            | 行为                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `list_servers`                  | 查询授权服务器的名称、Host、状态与标签                                         |
| `list_projects`                 | 列出授权范围内的项目                                                           |
| `list_tasks`、`get_task`        | 查询任务和目标状态                                                             |
| `get_project`                   | 查询仓库、服务与环境元数据                                                     |
| `draft_operation_plan`          | 生成多步骤运维方案草稿                                                         |
| `get_operation_plan`            | 读取页面选定方案版本的步骤名称与超时设置 |
| `inspect_servers`               | 用固定只读检查查询目标的构建工具、版本、Docker、Compose、磁盘与软件包安装状态  |
| `diagnose_deployment`           | 按任务和目标汇总结构化诊断，例如镜像拉取失败、安装超时或缺少工具               |
| `initialize_component`          | 在明确指定的目标运行固定版本的 Docker、Compose v2、Node.js 或 Nginx 初始化方案 |
| `execute_command`               | 为显式目标的远程 Shell 生成待确认提案                                          |
| `draft_source_change`           | 提供源文件修改建议，供人工审阅                                                 |
| `analyze_repository_deployment` | 按固定提交读取有限的仓库证据并提出构建和部署建议                       |
| `publish_source_branch`         | 将限定的文件变更写到独立的代码审查分支                                         |
| `open_pull_request`             | 从已推送的审查分支创建 PR，交由人工审核与合并                                  |

一次聊天最多 8 次工具调用；工具输出和响应大小受限。会话仅发起者可见，历史消息只发送最近必要上下文。用户消息、模型响应和工具记录会去除当前 Provider 密钥及常见密钥/密码模式，仍请不要将其他业务密码粘贴到聊天中。

## 权限模式

默认 `CONFIRM`。项目可覆盖默认模式；系统的资源边界、禁止规则和强制确认规则始终有效，项目不能扩大它们。

| 模式           | 允许的行为                                                                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `READ_ONLY`    | 在授权范围内查询、巡检、诊断和生成草稿。用户可采用或放弃草稿，在编辑器中审核采用的草稿。                                                        |
| `CONFIRM`      | 查询与巡检可直接进行。环境初始化、代码推送和创建 PR 分别生成提案。                                                               |
| `FULL_CONTROL` | 在授权的服务器执行已审核的固定安装方案，在明确授权的仓库推送审查分支及创建 PR。任意远程 Shell 仍需审批，PR 由人工合并。 |

VIEWER 可以查询授权元数据与状态。读取仓库内容、审批和执行写操作限管理员与操作员。`deniedActions` 优先于 `allowedActions`，`requireConfirmActions` 可为写入工具强制审批。查询和草稿也受 `deniedActions` 约束。批量请求包含任何未授权目标时整体拒绝。

`serverIds`、`projectIds`、`repositoryIds` 省略表示该级策略没有附加范围限制，显式空列表拒绝该类资源。FULL_CONTROL 的服务器操作要求明确的 `serverIds`，仓库变更需要明确的 `repositoryIds` 才可免审批。仓库 ID 可在项目的仓库详情中查看。`allowedActions` 省略表示沿用模式规则，显式空列表拒绝全部写入类别。


## 提案确认

提案绑定发起者及固定执行参数，15 分钟过期。审批只覆盖当前步骤。例如，先批准安装 Docker，确认任务完成后再运行执行流。推送审查分支和打开 PR 也分别审批。确认时重新核对角色、系统与项目策略以及目标绑定。拒绝或过期的步骤会结束。

确认用数据库原子状态更新消费提案。重复点击和并发请求最多提交一次；如果确认后平台崩溃或执行提交失败，不自动重试未知写操作，应先检查任务中心。实际执行仍由统一任务队列负责状态、取消、日志和审计，聊天文字本身不能替代提案确认接口。

## 分析仓库与交付配置

在项目关联的仓库页打开「AI 分析仓库」。可以直接分析远端默认分支，也可指定完整 Commit、仓库子目录或部署文档。分析固定到实际读取的 Commit，并从有限的源码入口、依赖清单、容器配置和说明文件识别技术栈、服务和构建命令。选择服务和环境可提供额外上下文。

核对固定提交、引用文件、依赖安装命令和发布路径。将审阅后的配置填入执行图开始节点，发布图版本并从对应开始节点预览运行。后续会支持可审阅的图草稿与按角色受控的执行流调用。[执行流交付](执行流交付.md)

## 目标巡检与部署排错

开始前检查指定目标的工具与服务状态。Debian 和 Ubuntu 目标可以按步骤从已有 APT 源安装 Docker、Compose v2、Node.js 或 Nginx，完成后再次巡检。Docker 与 Nginx 方案需要 systemd，安装均需要 root。Node.js 版本由系统软件源决定，安装后要核对项目要求。目标和运行环境明确后，从已发布的执行流预览固定的版本、提交、产物和目标。任务在后台执行时，可以在同一对话中查询结果并继续，后续写操作等上一任务结束再提交。

发布报错时，根据阶段、退出码和诊断类别核对原因。例如镜像拉取失败先检查 Registry 连通和授权，安装超时检查包管理器与磁盘，缺少依赖时核对运行时及项目依赖清单。诊断使用经过筛选的结构化结果。

需要修改项目文件时，先核对建议和基线提交。代码变更从授权仓库的固定基线建立独立审查分支。仅支持有限范围内的现有普通源文件和文档。工作流、部署脚本、凭据和受保护路径不接受自动写入。PR 支持 GitHub.com HTTPS 和 Gitea HTTPS 的仓库凭据，GitHub 创建草稿 PR。PR 创建后在仓库平台审阅差异、运行检查并人工合并。

## 交付结果分析

设置 `AI_PIPELINE_ANALYSIS=true`，并在系统设置中启用 OpenAI 兼容 Provider。Worker 先保存任务终态，再用任务诊断路由选择的 Provider 生成摘要、失败阶段与诊断建议。适用于支持任务结果摘要的交付任务。模型输入限于任务状态、目标计数、阶段和退出码，不包含日志、命令、仓库内容或环境变量。

任务详情展示分析结果。模型没有工具权限，15 秒内未完成、模型配置不可用或响应无效时显示「AI 分析暂不可用」，构建和部署结果以执行记录为准。Worker 关停或租约过期恢复时可能没有 AI 摘要。
