# AI 配置、工具与执行权限

AI 使用 OpenAI 兼容的 `POST {baseUrl}/chat/completions`，可不配置。未配置或 Provider 被禁用时，资源管理、Pipeline 与手工运维继续运行，聊天会给出明确提示。

## Provider

管理员在系统设置中配置名称、Base URL、模型、API Key 和超时。Base URL 可以是 `https://api.deepseek.com` 或带 `/v1` 的兼容端点，不要填写最终 `/chat/completions` 路径。模型名原样发送，不会自动替换。多个 Provider 时默认选择最早创建的启用项，聊天也可以指定 Provider。

API Key 由统一凭据服务用 AES-256-GCM 加密，Provider 只保存凭据引用。列表、编辑与测试响应不回显密钥；留空编辑密钥表示保留当前凭据。可禁用 Provider，也可引用现有启用的 `API_KEY` 类型凭据。生产使用 HTTPS；仅本机测试可使用 HTTP。HTTP 重定向不跟随，避免向重定向站点发送密钥。

DeepSeek 端点请求带 `thinking:{type:"disabled"}`，普通兼容 Provider 不附加该扩展参数。模型返回的推理字段不会展示或持久化。原始上游错误正文不回传，连接、超时与 HTTP 错误返回安全摘要。

## 业务工具

| 工具                     | 行为                                                       |
| ------------------------ | ---------------------------------------------------------- |
| `list_servers`           | 返回授权服务器的名称、Host、状态、标签；不返回凭据         |
| `list_projects`          | 列出授权范围内项目                                         |
| `list_tasks`、`get_task` | 查询任务和目标状态，不读取日志                             |
| `get_project`            | 查询仓库、服务与环境元数据                                 |
| `query_pipeline`         | 查询 Pipeline 与固定配置版本                               |
| `draft_pipeline`         | 生成 Pipeline 创建请求草稿，需人工检查与保存               |
| `draft_operation_plan`   | 生成多步骤运维方案草稿，不保存或执行                       |
| `inspect_servers`        | 固定只读命令 `uname -srm; uptime; df -h /`，不可自定义命令 |
| `execute_command`        | 提议在显式目标服务器执行 Shell，走统一命令中心与任务引擎   |
| `run_pipeline`           | 提议固定版本、Commit、环境与部署目标的 Pipeline 执行       |

本轮不提供凭据读取、原始数据库、任意网络请求、文件系统或直接 SSH 工具。仓库分析目前基于项目仓库元数据与用户提供的信息，不会声称已分析未读取的仓库源码。

一次聊天最多 8 次工具调用；工具输出和响应大小受限。会话仅发起者可见，历史消息只发送最近必要上下文。用户消息、模型响应和工具记录会去除当前 Provider 密钥及常见密钥/密码模式，仍请不要将其他业务密码粘贴到聊天中。

## 权限模式

默认 `CONFIRM`。项目可覆盖默认模式；系统的资源边界、禁止规则和强制确认规则始终有效，项目不能扩大它们。

| 模式           | 查询/草稿          | 执行                                                                                    |
| -------------- | ------------------ | --------------------------------------------------------------------------------------- |
| `READ_ONLY`    | 允许授权查询与草稿 | 命令和部署拒绝                                                                          |
| `CONFIRM`      | 允许               | 生成待确认提案，确认后提交任务                                                          |
| `FULL_CONTROL` | 允许               | 必须明确服务器范围；注册的固定只读巡检可直接提交，任意 Shell 与部署仍按未知风险要求确认 |

VIEWER 不能通过 AI 执行服务器操作。`deniedActions` 优先于 `allowedActions`；`requireConfirmActions` 可对注册工具强制确认。执行动作类别为 `execute_command`、`inspect_servers`、`run_pipeline`。查询与草稿工具也可被 `deniedActions` 禁止。

`serverIds`、`projectIds` 未配置表示不额外收窄 CONFIRM 的同团队资源权限；显式空列表表示不允许该类资源。FULL_CONTROL 要求非空 `serverIds`。`allowedActions` 省略表示沿用模式规则，显式空列表表示拒绝全部执行类别。批量请求含任意未授权服务器时整体拒绝。

## 提案确认

提案绑定发起者及不可编辑的执行参数，15 分钟过期。确认时重新检查当前用户角色、最新系统/项目策略、全部目标和服务器连接绑定；目标变化后必须重新生成。拒绝或过期不会执行。

确认用数据库原子状态更新消费提案。重复点击和并发请求最多提交一次；如果确认后平台崩溃或执行提交失败，不自动重试未知写操作，应先检查任务中心。实际执行仍由统一任务队列负责状态、取消、日志和审计，聊天文字本身不能替代提案确认接口。
