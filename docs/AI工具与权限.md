# AI 配置、工具与执行权限

AI 使用 OpenAI 兼容的 `POST {baseUrl}/chat/completions`，可不配置。未配置或 Provider 被禁用时，资源管理、Pipeline 与手工运维继续运行，聊天会给出明确提示。

## Provider

管理员在系统设置中配置名称、Base URL、模型、API Key 和超时。Base URL 可以是 `https://api.deepseek.com` 或带 `/v1` 的兼容端点，不要填写最终 `/chat/completions` 路径。模型名原样发送，不会自动替换。多个 Provider 时默认选择最早创建的启用项，聊天也可以指定 Provider。

API Key 由统一凭据服务用 AES-256-GCM 加密，Provider 只保存凭据引用。列表、编辑与测试响应不回显密钥；留空编辑密钥表示保留当前凭据。可禁用 Provider，也可引用现有启用的 `API_KEY` 类型凭据。生产使用 HTTPS；仅本机测试可使用 HTTP。HTTP 重定向不跟随，避免向重定向站点发送密钥。

DeepSeek 端点请求带 `thinking:{type:"disabled"}`，普通兼容 Provider 不附加该扩展参数。模型返回的推理字段不会展示或持久化。原始上游错误正文不回传，连接、超时与 HTTP 错误返回安全摘要。

## 业务工具

| 工具                            | 行为                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `list_servers`                  | 查询授权服务器的名称、Host、状态与标签                                         |
| `list_projects`                 | 列出授权范围内的项目                                                           |
| `list_tasks`、`get_task`        | 查询任务和目标状态                                                             |
| `get_project`                   | 查询仓库、服务与环境元数据                                                     |
| `query_pipeline`                | 查询 Pipeline 与固定配置版本                                                   |
| `draft_pipeline`                | 生成供采用或放弃的 Pipeline 草稿                                               |
| `draft_operation_plan`          | 生成多步骤运维方案草稿                                                         |
| `inspect_servers`               | 用固定只读检查查询目标的构建工具、版本、Docker、Compose、磁盘与软件包安装状态  |
| `diagnose_deployment`           | 按任务和目标汇总结构化诊断，例如镜像拉取失败、安装超时或缺少工具               |
| `initialize_component`          | 在明确指定的目标运行固定版本的 Docker、Compose v2、Node.js 或 Nginx 初始化方案 |
| `execute_command`               | 为显式目标的远程 Shell 生成待确认提案                                          |
| `run_pipeline`                  | 按固定版本、Commit、环境、目标和执行模式构建或部署                             |
| `draft_source_change`           | 提供源文件修改建议，供人工审阅                                                 |
| `analyze_repository_deployment` | 按固定提交读取有限的仓库证据并生成可审阅的 Pipeline 草稿                       |
| `publish_source_branch`         | 将限定的文件变更写到独立的代码审查分支                                         |
| `open_pull_request`             | 从已推送的审查分支创建 PR，交由人工审核与合并                                  |

一次聊天最多 8 次工具调用；工具输出和响应大小受限。会话仅发起者可见，历史消息只发送最近必要上下文。用户消息、模型响应和工具记录会去除当前 Provider 密钥及常见密钥/密码模式，仍请不要将其他业务密码粘贴到聊天中。

## 权限模式

默认 `CONFIRM`。项目可覆盖默认模式；系统的资源边界、禁止规则和强制确认规则始终有效，项目不能扩大它们。

| 模式           | 允许的行为                                                                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `READ_ONLY`    | 在授权范围内查询、巡检、诊断和生成草稿。用户可采用或放弃草稿，在编辑器中审核采用的草稿。                                                        |
| `CONFIRM`      | 查询与巡检可直接进行。环境初始化、Pipeline 执行、代码推送和创建 PR 分别生成提案。                                                               |
| `FULL_CONTROL` | 在授权的服务器执行已审核的固定安装方案，在授权配置下构建或部署，在明确授权的仓库推送审查分支及创建 PR。任意远程 Shell 仍需审批，PR 由人工合并。 |

VIEWER 可以查询授权元数据与状态。读取仓库内容、审批和执行写操作限管理员与操作员。`deniedActions` 优先于 `allowedActions`，`requireConfirmActions` 可为写入工具强制审批。查询和草稿也受 `deniedActions` 约束。批量请求包含任何未授权目标时整体拒绝。

`serverIds`、`projectIds`、`repositoryIds` 省略表示该级策略没有附加范围限制，显式空列表拒绝该类资源。FULL_CONTROL 的服务器操作要求明确的 `serverIds`，仓库变更需要明确的 `repositoryIds` 才可免审批。仓库 ID 可在项目的仓库详情中查看。`allowedActions` 省略表示沿用模式规则，显式空列表拒绝全部写入类别。

管理员在 Pipeline 的运行预览复制执行指纹，并填入策略的 `approvedPipelineHashes` 后，FULL_CONTROL 才能免审批执行对应的配置。指纹绑定版本、Commit、运行模式、环境及目标，任一绑定变化都需重新审核。系统和项目同时配置指纹名单时，执行必须同时在两份名单中。

## 提案确认

提案绑定发起者及固定执行参数，15 分钟过期。审批只覆盖当前步骤。例如，先批准安装 Docker，确认任务完成后再批准部署。推送审查分支和打开 PR 也分别审批。确认时重新核对角色、系统与项目策略以及目标绑定。拒绝或过期的步骤会结束。

确认用数据库原子状态更新消费提案。重复点击和并发请求最多提交一次；如果确认后平台崩溃或执行提交失败，不自动重试未知写操作，应先检查任务中心。实际执行仍由统一任务队列负责状态、取消、日志和审计，聊天文字本身不能替代提案确认接口。

## 从仓库生成构建流程

在项目关联的仓库页打开「AI 分析仓库」。可以直接分析远端默认分支，也可指定完整 Commit、仓库子目录或部署文档。分析固定到实际读取的 Commit，并从有限的源码入口、依赖清单、容器配置和说明文件识别技术栈、服务和构建命令。选择服务和环境可提供额外上下文。

核对草稿的固定 Commit、引用文件、依赖安装命令和发布路径。点击「采用草稿」将配置带入 Pipeline 编辑器，经审核后手工保存。点击「放弃草稿」结束本次选择。

## 目标巡检与部署排错

开始前检查指定目标的工具与服务状态。Debian 和 Ubuntu 目标可以按步骤从已有 APT 源安装 Docker、Compose v2、Node.js 或 Nginx，完成后再次巡检。Docker 与 Nginx 方案需要 systemd，安装均需要 root。Node.js 版本由系统软件源决定，安装后要核对项目要求。目标和运行环境明确后，使用固定 Pipeline 版本和 Commit 构建或部署。任务在后台执行时，可以在同一对话中查询结果并继续，后续写操作等上一任务结束再提交。

发布报错时，根据阶段、退出码和诊断类别核对原因。例如镜像拉取失败先检查 Registry 连通和授权，安装超时检查包管理器与磁盘，缺少依赖时核对运行时及项目依赖清单。诊断使用经过筛选的结构化结果。

需要修改项目文件时，先核对建议和基线提交。代码变更从授权仓库的固定基线建立独立审查分支。仅支持有限范围内的现有普通源文件和文档。工作流、部署脚本、凭据和受保护路径不接受自动写入。PR 支持 GitHub.com HTTPS 和 Gitea HTTPS 的仓库凭据，GitHub 创建草稿 PR。PR 创建后在仓库平台审阅差异、运行检查并人工合并。

## Pipeline 结果分析

设置 `AI_PIPELINE_ANALYSIS=true`，并在系统设置中启用 OpenAI 兼容 Provider。Worker 先保存任务终态，再用第一个启用的 Provider 生成摘要、失败阶段与诊断建议。适用于 Webhook 和手动 Pipeline。模型输入限于任务状态、目标计数、阶段和退出码，不包含日志、命令、仓库内容或环境变量。

任务详情展示分析结果。模型没有工具权限，15 秒内未完成、模型配置不可用或响应无效时显示「AI 分析暂不可用」，构建和部署结果以执行记录为准。Worker 关停或租约过期恢复时可能没有 AI 摘要。
