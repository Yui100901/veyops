# 执行流构建与部署

进入项目后默认打开「项目资源」。「执行图」用于编辑、发布和运行，「交付记录」用于回查构建产物、部署与回滚、待审批发布，「项目配置」用于基本信息、执行默认值、公共变量和项目 AI 策略。本页的操作路径以 `5708a11` 的工作台和预览为基线。

## 配置与编排

1. 在「项目资源」登记仓库、服务和环境，从服务详情关联仓库。服务器和分组在全局「服务器」登记。在环境详情保存「默认发布目标」及「环境文件」。在服务环境的「部署设置」保存发布目录、启停、健康检查和保护策略，按需覆盖默认发布目标。「服务器及来源」可查看直接引用、分组和引用状态。
2. 进入「执行图」的草稿画布。拖入 Git 拉取、加载环境、构建或部署模块，添加开始与结束节点，连线并配对。为需复用的流分别设定选边和输入绑定。
3. 在开始节点声明仓库、Git 版本、服务、环境、目标和制品等实际需要的参数。要从历史构建选择镜像，可添加 Docker 镜像类型的制品参数。结束节点声明要返回的本次构建产物或实际发布结果。
4. 在构建节点配置相对工作目录、安装和构建命令、构建位置与具名产物。部署节点绑定服务、环境、已登记制品及需要的目标输入，发布设置在服务环境维护。现有表单仍保留旧构建字段，旧流程按迁移方案比对后调整。新编排在构建节点明确来源，避免重复填写。
5. 保存草稿并执行发布检查。发布后从已发布开始节点运行，或从服务环境进入匹配的开始节点。服务环境链接预填适用的参数并保留返回位置，固定绑定继续随所选版本生效。

| 执行流 | 控制路径与关键绑定 |
| --- | --- |
| 仅构建 | Git 直达构建，结束返回本次具名产物。 |
| 审核并构建 | 选中经审核路径后进入同一个构建节点，审核使用本次固定源码。 |
| 构建并部署 | 将当前构建的具名结果绑定到部署节点，结束返回实际发布结果。 |
| 仅部署 | 将开始参数选中的历史产物绑定到同一部署节点，结束返回发布结果。 |

Shell 产生的文件也可参与交付。将已有工作区绑定给 Shell，按脚本参数设置相对输出路径，再通过产物登记节点检查和归档。下游消费已登记的引用。

## 构建与目标

Git 拉取接受分支、标签或完整提交。预览固定实际 SHA，记录检出来源。管理端 Shell、产物登记和构建可使用同一次运行内授权的工作区。目标端按固定提交在确认的构建服务器上准备隔离目录。

管理端仅构建在配置的隔离运行器执行，需要 Docker CLI 和可用的 Docker daemon。即使环境设了发布分组，管理端构建也无需展开该分组。目标端构建须提供构建节点所需的目标，缺项可在预览定位。发布阶段单独解析目标，依次使用允许运行选择的目标、服务环境覆盖和项目环境默认目标。已有旧部署目标继续显示其来源，待存量切换后再清理。

一个构建可声明多个具名结果，如 `jar` 文件、`static` 目录和 `image` 镜像。必需制品全部归档后才能给下游使用。目标端归档按来源服务器与目标匹配。文件记录校验值，镜像使用 Registry Digest 或已校验的离线归档。

## 环境文件与变量

项目公共变量在「项目配置」维护。项目环境变量在该环境详情维护，服务环境的覆盖项在其「变量」页保存。可先保存服务环境变量，再配置发布目标。变量读取按仓库环境文件、项目公共变量、项目环境变量、服务环境覆盖、节点显式绑定的次序进行。删除覆盖项后恢复继承。

同一固定 SHA 可以在测试加载 `.env.test`，在生产加载 `.env.prod`。加载环境节点绑定对应的 Git 工作区。节点指定文件时从节点工作目录解析相对路径。其后取环境配置中的仓库相对路径。当前版本最终按约定在该目录探测 `.env.<环境标识>` 和 `.env`。显式文件缺失、不可读或越出工作区时，按预览显示的仓库、提交和路径修正。约定文件未命中时可继续使用平台变量。多仓时为每个加载节点明确绑定一个源码工作区。

表格与 dotenv 文本视图编辑同一份变量数据。文本使用 `KEY=VALUE`，在对应赋值前添加 `# @secret KEY` 标记敏感变量。重复键、缺少赋值的敏感标记或语法错误需修正后保存。说明在表格维护，普通注释可用来理解导入文本。文本复制默认使用掩码，保留原标记和掩码可维持原值。替换时输入新值或选择获授权的凭据。管理员可单独查看敏感值，操作记入审计。

脚本可读取系统注入的 `VEYOPS_PROJECT_SLUG`、`VEYOPS_PROJECT_ID`，与服务关联时可读取 `VEYOPS_SERVICE_SLUG`、`VEYOPS_SERVICE_ID`。触发事件用 `VEYOPS_TRIGGERED_AT` 和 `VEYOPS_TRIGGER_COMMIT_SHA` 回查，`VEYOPS_GIT_COMMIT_SHA` 对应该工作区的实际检出提交。敏感变量加密保存，预览展示键名、来源和敏感状态，执行日志自动脱敏。

## 预览、确认与追溯

- 预览时核对图版本和路径、实际仓库及 SHA、环境文件、变量来源、构建位置及发布目标。检查展开后的成员、批次策略、产物来源及保护条件。有计划变更提示时重新预览并核对差异，再提交执行。同一确认请求可按幂等键取回原运行。
- 构建并部署消费本次指定节点的产物。预览时确认生产节点、具名输出及类型，实际 ID 随归档结果记录。构建失败时跳过依赖该产物的发布并保留当前服务。
- 仅部署可选择同项目、同服务、同环境的历史产物，或使用入口显式配置的「最新兼容」规则。预览固定实际制品 ID 和目标范围。目标端制品逐台校验来源，同一次部署使用同一构建批次。当前没有兼容产物时先运行对应构建流。
- 从运行详情进入「交付记录」，按服务、环境和提交找回产物或发布记录。检查生产图版本、节点、实际消费的制品、逐目标快照与任务日志。事件提交、实际检出 SHA 和产物来源分别核对。浏览器刷新或从日志返回时，查询参数保留记录及筛选。

## 发布保护、审批与回滚

在服务环境的「代码审核」中，管理员可登记或撤销完整提交 SHA 的审核。启用「要求代码审核」后，系统按产物实际来源提交核对审核有效性。图内审批处理流程中的等待，发布审批则在「交付记录 → 待审批发布」批准固定的制品、环境和目标。按仓库身份和多仓依赖核对审核覆盖仍属于后续验收。

文件发布把候选归档解包到 `deployPath/releases/<task-id>`，校验后原子更新 `current`。使用专用部署目录，首次发布检查空目录，后续发布检查归属标记。Docker Compose 文件应使用 `${VEYOPS_IMAGE}` 引用平台选定的镜像。Registry 产物按 Digest 拉取，导入离线归档前校验归档，导入后核对镜像 ID 与平台。

发布锁覆盖准备、激活和健康检查。候选版本激活后发生明确失败时，自动回滚按配置恢复上一次健康版本或固定健康基线。手动回滚从「部署与回滚」选择历史发布，预览并确认目标和制品快照。远端写入状态不确定时进入 `NEEDS_ATTENTION`，保留锁及排查信息。数据库与数据卷按 [备份与恢复](BACKUP.md) 单独处理。

产物适用全局或服务环境保留策略。当前运行版本、回滚基线、在途引用及人工固定制品受到保护。相关接口见 [交付记录与保护](API.md#交付记录与保护)。

## 测试和自动运行

可用 [示例仓库指南](../examples/README.md) 在隔离环境验证文件包、静态站点、Node.js 服务或 Docker Compose。先走同一固定 SHA 的双环境手动四流，再验证构建失败、缺失制品、目标变动、审批、部分失败和回滚。实机验收与存量切换以 [总体实施计划](需求梳理与实施计划.md) 的候选记录为准。

开始节点可配置 Cron、签名 Webhook、认证 API 和上游触发。为必填参数设置有效默认、固定值、事件映射或可验证的选择规则。外部写入的自动入口按各自的隔离、授权、去重、审核及恢复用例验收后启用。详见 [项目执行图需求与实施计划](项目执行图需求与实施计划.md)。
