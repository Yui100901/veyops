# 执行流构建与部署

新项目附带「最小构建并部署」草稿，共 8 个节点和 7 条连线。画布预置「构建并部署」「仅构建」「仅部署」三个独立入口。两个构建入口共享代码拉取和构建节点，两个发布入口共享部署节点和发布结束。每次运行沿所选入口到配对结束，拥有独立的工作区和结果。

草稿画布提供三个入口。

- 「添加执行流」选择一套模板及目录产物或 Docker 镜像，一次追加三个入口及其共享节点，并定位到新增的主入口。一次撤销可移除此组节点和连线。
- 「节点库」通过点击或拖拽添加单个节点。默认显示开始、结束、代码拉取、执行命令、构建、部署。条件分支、固定延时、源码审核、发布审批、发布健康检查、按产物回滚在「更多节点」中。
- 选中已配置的功能节点，点击「保存为复用节点」。项目有保存项时，节点库显示「复用节点」。添加到画布的节点各自保存一份配置。

功能节点详情直接显示当前动作和所属执行流。共享节点的配置对所属执行流生效。可显式「更换动作」并撤销更改。完整模板中的检查与测试使用与「执行命令」相同的表单。

旧版草稿与发布版供历史查阅。继续编排时点击「建立简化草稿」，确认清空当前草稿后可添加新模板。

## 建立并运行最小流程

1. 在项目资源登记 Git 仓库和服务。在平台服务器登记 SSH 凭据并确认主机指纹。
2. 在草稿选中「构建并部署」。选择一台执行服务器，再填写 Git 来源和关联服务。当前流程的检出、构建和发布都在所选服务器完成。
3. 使用「复制配置到其他入口」预览并复制共用设置。各入口可以独立调整仓库版本、执行服务器或触发规则。在共享构建节点填写工作目录 `app` 及安装、构建命令，文件部署按服务要求填写停止和启动命令。
4. 保存草稿，检查发布条件，核对版本和受影响的触发器后确认发布。检查结果会定位到要补齐的节点或字段。
5. 回到「项目发布」，从项目卡片运行「构建并部署」或「仅构建」。完成后可在「仅部署」中选择同一服务的历史产物。只有已发布的入口可以运行。

| 内置模板           | 构建并部署                                                               | 仅构建                                  | 仅部署                                    |
| ------------------ | ------------------------------------------------------------------------ | --------------------------------------- | ----------------------------------------- |
| 最小构建并部署     | 代码拉取 → 构建 → 部署 → 发布结束                                        | 代码拉取 → 构建 → 构建结束              | 部署 → 发布结束                           |
| 较完整的构建并部署 | 代码拉取 → 检查与测试 → 构建 → 发布审批 → 部署 → 发布健康检查 → 发布结束 | 代码拉取 → 检查与测试 → 构建 → 构建结束 | 发布审批 → 部署 → 发布健康检查 → 发布结束 |

「仅部署」默认在运行时选择产物。图可在产物库为空时发布。第一次运行仅部署前，先通过同一服务的构建入口生成产物。也可在开始节点明确选择固定历史产物或上游产物来源。

## 开始节点与运行工作空间

同一个开始节点可设置多组源码。版本可以是分支、标签或完整提交 SHA，留空使用仓库默认分支。手动运行采用已发布的 Git 版本，预览固定实际 SHA。每个仓库检出到执行目录下的一级目录，目录名取克隆地址末段并去掉 `.git`。有重名时发布检查会定位到相应源码项。代码拉取默认使用浅检出，节点执行选项可打开完整拉取。

每个入口选定一台具备已确认指纹和凭据的 SSH 服务器。系统默认使用 `~/.veyops/workspace`，项目可覆盖目标端工作根。标识为 `project1` 的项目使用 `~/.veyops/workspace/project1`，首次执行时创建目录。每次执行使用独立的 `<项目目录>/<执行 ID>`。

脚本的工作目录相对本次执行目录，默认为 `.`。在脚本内切换目录只影响当前命令。「仅部署」同样在开始节点选择执行服务器，发布区关联服务和产物来源。跨机交付可在同一项目配置两条执行流，第一条在构建服务器留档，第二条用上游成功触发并在发布服务器消费可分发的产物。

平台设置的「单服务器执行流并发数」作用于每台服务器，各项目共享这台服务器的执行槽。同一服务器上的执行流按入队顺序运行，等待审批的运行仍占一个执行槽。其他服务器按各自队列同时执行。

变量从低到高按仓库 dotenv 文件、项目公共变量、所选变量集合、开始节点变量覆盖。仓库文件选项引用明确的源码和相对路径，并随源码固定到提交。变量集合支持表格和 dotenv 文本编辑，可用 `# @secret KEY` 标记敏感值。开始节点的敏感变量由凭据提供，运行记录保留掩码。平台系统变量包括 `VEYOPS_PROJECT_ID`、关联服务的 `VEYOPS_SERVICE_ID`，以及本次工作区和运行 ID。

## 留档与发布

实际执行过工作区动作的运行默认保留整个执行目录，直接登记为目录产物。打包下载和分发时自动过滤平台已识别的敏感配置及 Git 元数据。校验会核对登记时的完整性记录。结束节点可将保留范围改为仅供本次运行。关闭保存后，使用本次文件发布时仍会保留临时交付产物，活跃发布继续保护其实物。

文件部署使用本次目录产物或选定的历史产物，发布整个可分发目录。仓库 `app.git` 构建生成 `app/dist` 时，可以在启动命令中进入 `app/dist` 后启动服务。目标端发布状态由系统在项目目录内管理。成功发布后在服务详情查看当前版本。构建失败时，后续部署停止。

同一项目服务在每台服务器上沿用已分配的发布位置。修改工作根目录或项目标识后，新运行的工作目录和新服务器的首次发布采用新设置。已有服务器的续发、回滚和健康核对继续使用原位置。

已有管理端目录归档经核验后可作为目标端的历史输入。文件发布会核对归档大小和 SHA-256。

审批针对本次固定的发布目标和产物。具有审批权限的操作者在运行详情确认后继续。健康检查核对本次已激活的发布目标，结束节点可要求激活或要求健康。历史重发使用已选产物，结束节点核对该产物的实际发布结果，沿用本次配置的审批与健康检查要求。

纯构建流留空所属服务时，产物登记在项目下。指定所属服务后，该服务的发布流可选用这些产物。纯构建可按需在结束节点添加镜像登记项，名称可从已配置源码生成，也可手填如 `team/api`。内置 Dockerfile 构建选中登记后，由平台以实际 Image ID 设置本次 Tag。使用目标端的自定义构建命令时，可执行 `docker build -t "team/api:$VEYOPS_IMAGE_TAG" .`，构建服务器需具备 Docker 命令和执行权限。每次运行的标签使用完整运行 ID。Registry 来源填写完整的固定 Digest 引用。工作区和镜像独立留档。

Compose 发布在开始节点选择本次镜像登记项。只有一项时可以直接使用。使用工作区中的 YAML 时，平台在审批或发布前为选中的镜像固定配置摘要。也可指定固定提交中的 YAML，或在历史重发时使用当次镜像随附的配置。关联触发可在下游开始节点按登记名称选中上游同次运行的一项持久产物。历史重发始终使用已选实例 ID。独立的按产物回滚流须选择各目标曾成功发布的旧产物，预览固定当前版本，审批确认后再回滚。

「仅构建」可在构建结束的镜像登记项填写 Compose 相对路径，让镜像归档附带已校验的配置。「仅部署」复用所选镜像及配置，发布结束只执行当前路径的发布核对。

同一仓库包含多个组件时，可在检出后使用并行与汇合节点组织构建。互不重叠的构建目录可以并行。结束节点为每个 Dockerfile 构建配置一个镜像登记项，开始节点选择需要交付的整组镜像。Compose 用 `${VEYOPS_IMAGE_FRONTEND}` 和 `${VEYOPS_IMAGE_BACKEND}` 等变量引用配置的登记项，平台逐一核验镜像 ID 及激活结果。

管理端镜像归档由平台保留与清理。目标端登记的命名镜像、共享镜像引用和 Registry 镜像由相应 Docker 主机或仓库的策略管理。平台清理这类产物时解除登记引用，保留镜像实物。

表单按节点功能显示执行选项。画布中的功能节点可重复添加，节点通过执行顺序和本次工作区共享结果。

## 从历史目录构建

在「仅构建」的更多操作选择「从历史目录构建」，或在运行参数切换工作区来源。选择同项目的持久目录产物后，预览显示来源运行、提交和本次执行位置。平台核验并将产物内容还原到此次执行 ID 的新目录。代码拉取记录为成功并注明已复用历史目录，构建和留档使用新目录，原产物继续供历史发布或其他构建引用。

有代码拉取动作的纯构建入口可以保存并发布空源码列表。此时每次手动运行必须先选择历史目录，自动触发无法启用。配置了仓库变量文件时，预览需要在产物记录的固定提交中核对该文件。目标端可使用已校验的历史归档，也可从同机或其他登记的构建服务器复制目录。

已发布版本的配置和运行证据按发布时的快照保留。草稿含旧入口字段时，确认检出目录、所选执行服务器与启动命令，保存后再发布。

## 触发与运行记录

Cron、仓库轮询、签名 Webhook、认证 API 和上游规则都在开始节点配置。仓库轮询或推送按源码组匹配仓库和分支，使用匹配事件的完整 SHA。多组源码匹配时需要明确来源。同一项目内，上游成功规则以紫色虚线箭头从结束节点连到下游开始节点。上游产物继承适用于目标开始节点启用对应选项的规则。自动构建和发布继续检查平台白名单、服务器授权和原有审批。已受理运行保留确认时的图版本和执行计划。

任务中心按完整执行流显示一条任务。任务中心与项目运行记录共用运行详情，默认查看全部节点，也可在画布或下拉框选择单节点。详情画布按本次执行流的依赖重新排布，草稿保持原坐标。可以查看节点日志、实际提交、发布结果和工作目录。

服务详情按目标和发布位置分别显示当前版本与最近尝试，失败目标也可跳到原运行核查。数据库与服务持久数据使用独立的[备份与恢复](BACKUP.md)流程。
