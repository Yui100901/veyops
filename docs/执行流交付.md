# 执行流构建与部署

项目工作台包含「项目资源」「执行图」「产物」「项目配置」。服务负责访问地址和仓库关联，变量集合提供可复用的运行变量。构建、发布、审核、审批、健康检查和回滚的顺序由已发布执行图声明。

## 配置与编排

1. 在「项目资源」登记仓库和服务，按需登记变量集合。在平台「服务器」选用已登记的 SSH 服务器或分组。进入服务详情可以查看访问地址及相关执行流。
2. 打开新项目的「执行图 → 编辑草稿」。选中「最小构建并部署」的开始节点，设置项目仓库、Git 版本、构建位置、项目服务和发布目标。构建位置可选「沿用平台设置」「管理端」或「目标端」。选择目标端后可指定服务器或分组。构建端与发布端为同一台服务器时，选择目标端和这台服务器，再开启「构建与发布同一台服务器」。在工具栏也可以插入其他流程模板。
3. 在构建节点的「执行」填写安装与构建命令，必要时设置相对工作目录。在部署节点选择发布方式、发布目录和产物来源。使用默认的构建工作目录快照做文件发布时，选定要发布的产物子路径，或明确选择发布整个目录。
4. 点击「保存并检查发布」。通过后核对执行流和触发规则的影响，再点击「确认发布」。检查有误时从诊断跳到相关字段，已保存的草稿可以继续编辑。可以单独「检查发布条件」或「保存草稿」。遇到修订冲突时本地修改会保留，使用「放弃本地更改，载入服务器草稿」可主动载入最新修订。
5. 前往「构建发布」并点击「立即运行」，使用已发布的默认配置。临时更换允许覆盖的 Git 版本时使用「带参数运行」。通过运行详情查看实际提交、产物和日志，通过服务详情查看当前版本与最近发布尝试。

| 内置模板 | 默认接线 |
| --- | --- |
| 最小构建并部署 | 开始 → 代码拉取 → 构建 → 部署 → 结束。结束返回本次主产物和发布结果。 |
| 较完整的构建 | 开始 → 代码拉取 → 检查与测试 → 构建 → 结束。检查通过后构建并保存产物，同时返回检查报告。 |
| 较完整的部署 | 开始 → 人工审批 → 部署 → 发布健康检查 → 结束。可选择已登记的历史产物，结束返回经检查的发布结果与健康状态。 |

模板插入时可选文件、目录或 Docker 镜像，默认目录。草稿可以先保存，发布检查会定位待补配置。源码审核可关联实际构建并绑定 `review` 凭证。选择旧产物后会生成一次新的发布。图内回滚使用「按产物回滚」节点，绑定本次发布结果 `afterRelease` 并核对逐目标基线。

同一执行流的普通出线并行，普通节点或结束的多条入线等待本次参与的上游。条件分支按匹配值选择稳定的出口 ID，未匹配时走默认出口。主工作区可交给自定义 Shell 或检查节点，在「输出」声明正式产物。关闭保留的产物由当前根运行及其子流消费。

将检查或 Shell 设为「目标端」时，可绑定检出节点的工作区，并用开始配置选择服务器。运行预览显示服务器、工作目录、工作区来源和已固定的提交。预设动作的专用选项在节点「执行」配置，自定义 Shell 可声明自己的输入、输出和局部环境变量。旧草稿若在预设步骤设置了固定仓库、版本、执行位置或目标，先在开始节点配置需要的资源，再从诊断定位并清除旧值。

重新发布旧草稿时，检出和构建节点的固定仓库或 Git 版本也会触发诊断。将固定值移到开始节点，或将节点输入接到可靠的上游源码，再检查发布。已发布版本和已有运行继续使用各自的配置快照。

## 源码与发布组合

同一个开始节点可以设置多组源码，例如「联调」使用 API 仓库的 `main`，「发布」使用同一仓库的 `release/1.5`。检出节点在「数据来源」使用一个「源码」选项，切换时仓库及 Git 版本一起更新。Git 版本可指定分支、标签或完整提交 SHA，清除版本后采用组内仓库的默认分支。画布显示所选仓库及版本，点击详情中的来源可以返回开始配置。构建通常继续使用上游检出的工作区和 Git 来源，直接消费开始源码的构建使用相同的组选择。

发布组合把服务与服务器或分组保存在一起。可以为同一服务添加两组不同目标。部署节点选择「发布组合」后，服务和目标根据该组解析。只有一组时自动使用，单目标同机构建时可共用开始节点的构建位置。改名或调整组合顺序保留引用。需要移除正在使用的组合时，先从开始节点列出的使用情况切换有关节点的来源。

开始节点的运行时开关控制哪些字段可临时覆盖。使用「带参数运行」更换版本只作用于本次运行和所选源码组，下一次运行继续使用已发布的默认值。外部已登记产物在开始节点选择固定实例、最新兼容产物或由运行时提供。本次构建产物从上游节点传到部署步骤。

## 构建与变量

Git 拉取接受分支、标签或完整提交。预览固定实际 SHA。管理端构建在配置的隔离 Docker 运行器执行，可省略发布目标。目标端在确认的服务器准备独立工作区，默认根目录为 `~/.veyops/workspace`，项目可覆盖。

变量按仓库文件、项目公共变量、开始节点变量集合、节点显式绑定逐层覆盖。将变量文件加载节点绑定到固定源码，并填写明确的相对路径，或将 `ENV` 映射到 `.env.test`、`.env.prod`。必需文件缺失会阻止消费者执行；可选文件缺失时显示跳过。

变量集合支持表格和 dotenv 文本编辑。用 `# @secret KEY` 标记敏感变量，保留掩码时沿用原值。敏感值的明文查看受权限限制并写入审计。构建节点可将检出的 `commitSha` 绑定到 `GIT_SHA`，并在预览及运行详情核对来源。`VEYOPS_*` 系统键由平台注入。

## 工作目录与产物

构建、检查和 Shell 的「工作目录」相对实际工作区根目录，留空使用 `.`。每个独立命令从该目录开始，脚本内部的 `cd` 只作用于该段脚本。执行端核对目录存在且路径无链接跳转。

构建的目录产物默认「保存工作目录」。例如将工作目录设置为 `apps/api`，同一次构建可以保存 `dist/` 和 `reports/`。登记时生成独立的快照与完整目录摘要，同时记录实际 Git SHA 和构建位置。Git 元数据、平台目录、`.env` 文件及手工列出的排除路径会跳过。使用「仅保存指定路径」可只登记相对工作目录的某个交付文件或子目录。可关闭持久化，临时产物供当前根运行和子流使用。

文件发布填写相对产物根的 `dist/`，并单独填写目标主机发布目录，例如 `/srv/api`。检查或 Shell 填写 `reports/` 后，会自动接上每条可达路径都能提供的唯一目录产物。有多个候选时从输入中选择，显式绑定优先。脚本可从 `$VEYOPS_ARTIFACT_DIR` 读取展开后的内容，使用整个快照须显式填 `.`。预览固定已有产物实例，或固定本次运行的上游来源。取用时从已登记实例重新核对，历史重发仍可选择旧快照及其中的子路径。

目标端产物留在构建服务器，优先使用匹配的同机实例。只有一个可核对的文件产物实例时，可通过平台分发给其他目标。Docker 镜像独立登记实际 Image ID 或 Registry Digest。脚本镜像可在「输出」填写相对执行目录的 Compose 文件路径，并在部署时选择「产物自带模板」。

## 运行记录与日志

在执行图的「运行记录」打开一次运行，用上方画布或「定位节点」切换节点，下方直接显示该节点详情和日志。滚动查阅日志时，画布可留在页面顶部，也可以收起。通过「返回运行记录」回到列表。

服务详情为各个目标和发布位置分别显示当前激活版本和最近发布尝试。部署已开始准备且在连接、实物校验或取得发布锁时失败，可从最近尝试打开该次运行和节点日志。首次失败时当前版本为空。有旧版在运行时，服务仍显示旧版和本次失败原因。预览被拒或因上游失败而跳过部署，可在运行记录追查流程。

## 发布保护、审批与回滚

- 源码审核在相关运行节点处理。关联构建的审核固定主仓、依赖仓和独立变量文件的实际仓库及 SHA。发布审批固定本次服务、服务器成员、实物实例和指纹。计划或权限变化时需重新核对。
- 文件发布校验归档并准备 `deployPath/releases/<task-id>`，再更新 `current`。Docker Compose 的模板可以来自产物归档，或固定仓库、提交与路径。Compose 文件通过 `${VEYOPS_IMAGE}` 使用已验证的镜像。预览及应用时核对模板内容摘要。
- 健康探针在已激活的版本目录执行。退出码 `0` 表示健康，`10` 表示明确不健康。「健康才通过」模式在不健康时终止该链的后续步骤并保留检查证据。「报告健康状态」模式可用条件分支进入已配置的回滚。缺工具、超时、SSH 中断或发布结果不确定时进入待核查。
- 从运行详情对异常服务器发起只读核查，查看当前链接、发布锁和可确认的版本。符合条件时，从原版本重新预览。回滚恢复应用发布，数据库及持久数据使用独立的[备份与恢复](BACKUP.md)流程。
- 「产物」可查询、验证、固定保留、提交清理或跳到生产节点。同一主机上的独立发布位置分别保护活动产物。当前版本、最近健康版本及执行中保留的产物由清理规则保护。

服务环境默认发布目标、单独部署目标及旧交付操作属于历史记录。新发布、审批和回滚在执行图及运行详情操作。

## 演示和验收候选

[星桥商城演示](../examples/refactor-stage0/README.md) 使用固定 Git 快照、两组变量和两组目标。可在画布用预设重新编排，也可用初始化器在专用实例导入。Linux 验收脚本接受同一候选提交和镜像，分别建立 SQLite 或 PostgreSQL 空库。测试结果按修订稿 A01–A34 记录。 [实施顺序](项目交付重构实施计划.md#验收恢复后的顺序)

Cron、仓库轮询、签名 Webhook、认证 API 和上游规则在开始节点配置。Cron 使用已发布配置。仓库轮询与推送根据已发布源码组匹配仓库和分支，只为匹配的检出固定事件 SHA。若有多个检出同时符合规则，预检要求确定唯一来源。新版本发布时重新检查启用规则，已受理的运行保留原计划。

本轮 Chrome 界面回归使用模拟 API，覆盖同仓多源码、发布组合、同机器配置、改名和排序保留引用、阻止移除被用项，以及保存后检查、取消或确认发布、缺项诊断和修订冲突。实物构建和发布结果以对应的实机验收记录为准。
