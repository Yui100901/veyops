# 执行流构建与部署

从「项目详情 → 执行图」开始交付。每个项目有一张画布，每个有效的开始节点定义一个执行流。构建和发布配置随执行图版本保存。运行从对应开始节点发起，版本、参数、产物和目标以执行预览为准。

## 配置执行流

1. 在项目中登记代码仓库、具体服务、环境及测试服务器。按需在服务环境设置变量、默认服务器或服务器组、发布目录和发布保护。
2. 打开项目的「执行图 → 编辑草稿」，添加并连接开始节点和结束节点，再关联这两个端点。开始节点名称会成为执行流名称，多个开始节点可以共享一个结束节点。右键节点可复制或删除，右键连线可断开。
3. 选中开始节点，指定执行流预设和关联服务。选择「插入预设节点」可将所需节点放在已直连的开始和结束之间。也可手动添加节点。部署必须关联实际接收发布的服务，构建必须关联产物所属的服务。
4. 保存草稿并发布。在「执行图 → 运行执行流」的发布版画布点击开始节点，选择运行参数，预览并确认。图和流程运行保留各自的历史。

| 预设 | 默认用途 | 适用场景 |
| --- | --- | --- |
| 自定义 | 自由组合功能节点和分支 | 在一张图中编排独立的业务流程 |
| 构建归档 | 固定 Git 提交，执行构建并归档产物 | 生成可稍后发布的文件包或镜像 |
| 部署构建产物 | 选择同服务可用产物并发布 | 采用最新构建、重新部署历史构建 |
| 构建并部署 | 先构建，再部署本次产物 | 将已确认的提交发布到测试或目标环境 |
| 验证 | 通过核对步骤报告结果 | 集成检查、上线前巡检和环境核验 |
| 维护 | 按计划或手动安排项目维护 | 维护窗口、备份后检查和例行核对 |
| 发布审核 | 等待管理员批准，并记录结果 | 变更评审、值班交接和发布前确认 |

验证会插入 Shell，维护会插入审批和 Shell，发布审核会插入审批和日志。编辑者需为 Shell 指定目标和脚本，并按实际场景补充检查或记录内容。

## 构建流

在开始节点配置仓库、分支或固定提交、仓库内工作目录、构建位置、产物类型、安装及构建命令。分支会在预览时解析为完整提交。没有指定分支或提交时，使用仓库的远端默认分支。管理端和目标端都按固定提交构建。构建结果可从执行记录和项目交付页查看，下载归档时可核对 SHA-256。

| 构建位置 | 文件包 | Docker 镜像 |
| --- | --- | --- |
| 目标服务器 `TARGET` | 目标端构建，归档后回传，部署时按来源目标匹配 | 各目标端构建，各自归档或将镜像推送至 Registry |
| 管理端 `MANAGER` | 在隔离的构建容器生成一份归档，可用于匹配的多台目标 | 使用管理端 Docker 构建并归档或推送镜像，部署按快照中的不可变 Digest |

管理端构建需要 Docker CLI 和可访问的 Docker daemon。可信检出和打包镜像可由 `BUILD_HELPER_IMAGE` 配置，默认使用 `node:22-bookworm`。默认 Compose 部署不挂载 Docker Socket，使用管理端构建前需配置可运行的 Docker 环境及工作目录。

支持 HTTP(S) Git 仓库。私有仓库使用加密的 Git Token 或用户名密码凭据。源码拉取节点也可独立验证分支、固定提交及拉取深度，它在管理端临时目录运行。它的工作目录尚未作为其他节点的运行输入。

## 环境变量

在项目资源配置公共变量，在环境中配置差异。运行时项目公共变量先加载，环境覆盖同名变量。在关联服务并选择环境时，已有的服务环境变量最后覆盖。独立 Shell 流可选择执行环境，也可只使用项目公共变量。

表格和 `.env` 文本编辑共享变量，切换时同步未保存的修改。表格支持类型和说明。文本使用 `KEY=VALUE`，在对应赋值之前添加 `# @secret KEY` 标记敏感变量。粘贴整段 dotenv 进行批量编辑。导出默认使用掩码，可按权限显式查看敏感值。保存掩码保留原值，输入新值才替换。重复键和未匹配的敏感标记需要修正后才能保存。

说明保存在表格字段中。其他注释可出现在粘贴的文本中，保存后只保留变量数据。少数无法用单一引号包围的值使用平台支持的转义形式，交给外部 dotenv 工具时需核对解析结果。

项目配置中的「唯一标识」通过 `VEYOPS_PROJECT_SLUG` 注入 Shell、构建和发布脚本，系统 UUID 通过 `VEYOPS_PROJECT_ID` 注入。开始节点关联服务时，同时注入 `VEYOPS_SERVICE_SLUG` 与 `VEYOPS_SERVICE_ID`。敏感值加密存储，运行时按凭据引用读取，并对执行输出进行脱敏。

## 部署流

在运行表单选择环境和目标。选项「最新可用构建产物」会在预览时选定这个项目、服务和环境下的可用构建。也可显式选择某次历史构建。同一次部署使用一批产物。目标端构建的制品须匹配来源服务器，文件格式、镜像仓库、摘要和发布配置也须匹配。没有可用产物时不能部署，应先运行同服务的构建流。

预览列出确定的产物、提交和目标。新构建出现、指定归档失效、目标成员或部署配置变化时，提交需要重新预览。组合流默认使用本次构建结果进入部署，构建失败时无法进入发布节点。

文件发布把候选版本解包到 `deployPath/releases/<task-id>`，校验后原子更新 `current`。部署目录须为专用目录，首次部署要求为空，后续发布检查归属标记。运行命令和健康检查在候选版本准备完成后执行。发布加锁覆盖准备、激活和健康检查，远端结果不明确时保留锁供核查。

Docker Compose 的发布文件应以 `${VEYOPS_IMAGE}` 引用平台选定的镜像。对于 Registry 产物，运行时按 Digest 拉取。对于离线归档，导入前核对归档校验和，导入后核对镜像 ID 和平台。通过目标配置的 Registry 凭据完成鉴权。

## 发布审批和回滚

服务环境可要求发布前审批。管理员核对已固定的产物、环境和目标后在项目交付页批准待发布任务。执行前继续复核权限、目标和产物。拒绝、取消或健康检查失败都保留可追溯状态。

可在部署记录中选择有可用产物和快照的历史发布，预览并确认回滚。已配置自动回滚的环境在候选版本激活后发生明确启动或健康失败时，按上一次健康版本或固定的已验收版本尝试恢复。远端执行状态无法确定时进入 `NEEDS_ATTENTION`，需先核对目标实际状态。回滚应用版本时，数据库和数据卷使用各自的备份恢复流程。

产物受全局或服务环境的保留策略管理。正在运行的版本、回滚基线、待执行引用和人工固定的产物受到保护。下载、保留策略和审批接口见 [API 文档](API.md#交付记录与保护)。

## 试用和计划

可使用 [示例仓库指南](../examples/README.md) 配置文件包、静态站点、Node.js 服务或 Docker Compose。建议先在独立测试环境验证构建、默认产物选择、显式历史产物以及缺少产物时的拒绝，再评估生产发布配置。

开始节点仍可配置本地控制流的 Cron、签名 Webhook、认证 API 和上游触发。源码、SSH 与交付类执行流当前通过开始节点预览后手动确认。交付触发、跨环境制品提升、共享工作目录和制品传递计划见 [项目执行图需求与实施计划](项目执行图需求与实施计划.md)。
