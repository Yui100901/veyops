# 执行流构建与部署

新项目附带「最小构建并部署」草稿。每条执行流由一个开始节点、若干功能或条件节点和一个指定的结束节点组成。开始节点选择运行资源，功能节点按图使用当前运行的同一个工作区，结束节点决定留档和验收要求。

## 建立并运行最小流程

1. 在项目资源登记 Git 仓库和服务。在平台服务器登记 SSH 凭据并确认主机指纹。可选一台服务器或分组作为发布目标。
2. 在执行图草稿选择「最小构建并部署」的开始节点。配置 Git 来源、构建位置、服务、发布目标、发布目录和发布内容路径。例如仓库地址以 `app.git` 结尾，构建生成 `dist/` 时，发布内容路径填写 `app/dist`。
3. 在构建节点填写工作目录 `app` 和安装、构建命令。文件部署可按服务要求填写停止和启动命令。结束节点默认保存工作区并核对发布已激活。
4. 保存草稿，检查发布条件，核对版本和受影响的触发器后确认发布。检查结果会定位到要补齐的节点或字段。
5. 回到构建发布工作台运行已发布流程。使用「带参数运行」可临时覆盖开始节点明确开放的字段。查阅运行详情中的各节点和日志，从服务详情核对目标的当前版本及最近尝试。

| 内置模板       | 执行顺序                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| 最小构建并部署 | 开始 → 代码拉取 → 构建 → 文件部署 → 结束。                                                                   |
| 较完整的构建   | 开始 → 代码拉取 → 检查与测试 → 构建 → 结束。结束登记工作区。                                                 |
| 较完整的部署   | 开始 → 人工审批 → 文件部署 → 发布健康检查 → 结束。开始节点选择已登记的历史产物，或让上游规则提供可重用产物。 |

## 开始节点与运行工作空间

同一个开始节点可设置多组源码。版本可以是分支、标签或完整提交 SHA，留空使用仓库默认分支。预览固定实际 SHA。检出目录由克隆地址末段去掉 `.git` 得到，可为每组源码选择相对父目录。同名或互相包含的目录会在校验时提示修正。代码拉取默认使用浅检出，节点执行选项可打开完整拉取。

运行位置可选沿用平台设置、管理端或目标端。管理端脚本使用平台隔离的 Docker 运行器。目标端需选择一台具备已确认指纹和凭据的 SSH 服务器，也可选择只解析到一台服务器的分组。目标端工作根目录默认是 `~/.veyops/workspace`，项目可覆盖。每次运行使用独立工作区。所有脚本工作目录以本次工作区为起点，默认为 `.`。在脚本中切换目录只影响本条命令。若配置构建和发布同机，发布复用本次选定的目标端服务器。

变量从低到高按仓库 dotenv 文件、项目公共变量、所选变量集合、开始节点变量覆盖。仓库文件选项引用明确的源码和相对路径，并随源码固定到提交。变量集合支持表格和 dotenv 文本编辑，可用 `# @secret KEY` 标记敏感值。开始节点的敏感变量由凭据提供，运行记录保留掩码。平台系统变量包括 `VEYOPS_PROJECT_ID`、关联服务的 `VEYOPS_SERVICE_ID`，以及本次工作区和运行 ID。

## 留档与发布

文件部署从本次工作区快照或开始节点选定的历史目录产物读取。在开始节点指定相对产物根的内容路径，填写 `.` 表示整个目录。快照在首次发布准备或审批前固定。结束节点可设置保存工作区、排除路径及保留范围。仅本次运行保留的快照供本次使用，持久产物可从项目产物页查看及再次选用。成功的文件发布在服务详情显示当前版本。构建阶段失败时，部署动作不会激活新版本。

审批针对本次固定的发布目标和产物。具有审批权限的操作者在运行详情确认后继续。健康检查核对本次已激活的发布目标，结束节点可要求激活或要求健康。需要重发历史版本时，从使用历史制品的发布流发起新运行并重新审批。

构建流可在开始节点给产物指定所属服务，方便该服务后续选用。Compose 发布使用工作区相对路径、固定提交里的 YAML 或历史镜像中的配置。指定 Dockerfile 的内置构建会生成运行专用标签，登记实际 Image ID。自定义镜像按结束节点的引用登记，使用 Registry 时需填写其固定 Digest。独立的按产物回滚流须选择各目标曾成功发布的旧产物，预览固定当前版本，审批确认后再回滚。

旧发布版继续保留为历史记录。新编排使用开始节点资源配置和结束节点留档，新版表单按功能显示执行选项。画布中的功能节点可重复添加，节点通过执行顺序和本次工作区共享结果。

## 触发与运行记录

Cron、仓库轮询、签名 Webhook、认证 API 和上游规则都在开始节点配置。仓库轮询或推送按源码组匹配仓库和分支，使用匹配事件的完整 SHA。多组源码匹配时需要明确来源。上游产物继承适用于目标开始节点启用对应选项的规则。自动构建和发布继续检查平台白名单、服务器授权和原有审批。已受理运行保留确认时的图版本和执行计划。

在运行记录打开一次运行，使用顶部画布切换节点，在下方查看工作目录、实际提交、发布结果和日志。服务详情按目标和发布位置分别显示当前版本与最近尝试，失败目标也可跳到原运行核查。数据库与服务持久数据使用独立的[备份与恢复](BACKUP.md)流程。
